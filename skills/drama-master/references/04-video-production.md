# 视频生成执行规范

## 概述

将提示词转化为实际的AI视频片段。本模块负责批量生成调度、任务管理、重试策略、版本管理。**三条最高优先级铁律**：
1. **Seedance 2.5 为默认且最高优先级视频生成引擎**，提示词原文透传不改写，生成前必须用户确认
2. **有台词必须写进提示词**，让AI模型直接生成带语音的视频，不使用TTS单独合成
3. **每生成完一个视频必须以内嵌预览播放器形式交付**（用户可直接在聊天中点击播放预览），用户预览确认后再继续生成下一条，同时附公共访问链接

---

## 一、Seedance 2.5 最高优先级引擎

### 1.1 引擎优先级

| 优先级 | 引擎 | 适用场景 |
|---|---|---|
| ⭐ 最高（默认） | **Seedance 2.5** | 所有视频生成的默认选择，除非用户明确指定其他引擎 |
| 备选 | 即梦（横屏电影/竖屏Seedance/通用竖屏） | 用户明确要求即梦平台，或需要即梦特定风格引擎时 |
| 备选 | MiniMax H3 | 用户明确要求MiniMax平台时 |

**铁律**：默认使用 Seedance 2.5，不得因画质判断/速度/成本/时长或其他偏好自动切换到其他模型。仅当用户明确指定其他引擎时才切换。

### 1.2 原文透传规则

用户确认的最终视频提示词必须**逐字原文透传**给视频生成工具，具体要求：
- 不扩写、润色、精简、翻译、纠错或重排
- 不增加标题、前缀、后缀、负面提示词、镜头说明、风格词、质量词或结构化模板
- 不改变标点、空格、换行、大小写、语言、数字、符号或拼写
- 不把参考素材说明、工具参数、确认摘要或系统说明拼接进 prompt
- 不从聊天中的其他文字推断并补写 prompt

若用户要求修改提示词，先让用户提供或确认修改后的最终版本；得到最终版本后，仍按原文透传。

### 1.3 生成前确认（必须执行）

每次生成前必须向用户展示完整确认信息并等待明确确认，即使用户一开始已提供全部参数也不得跳过。确认信息至少包括：

```
【生成前确认】
模型：seedance_2.5（固定）
任务类型：文生视频 / 图生视频
原始 prompt：
```
[用户确认的原始提示词，逐字展示，保留原有换行和符号]
```
时长：XX秒（用户指定 / 根据创作类型自动建议）
比例：XX:XX（用户指定 / 根据创作类型自动建议）
参考素材：[列出是否使用及其独立输入职责]
检索补充：[列出准备采用的事实/视觉参考；未触发时写"无"]

是否按以上信息使用 Seedance 2.5 生成？
```

只有用户表达明确的肯定生成意图后才调用视频工具。沉默、部分回答、继续提问、模糊表态或只修改某一项均不算确认。用户修改任一项后，更新完整确认信息并重新等待确认。

### 1.4 时长与比例限制

**时长**：Seedance 2.5 支持整数 5-30 秒。超出范围时请用户改选时长，不得切换模型。

**比例**：仅支持以下 6 个精确值：`16:9`、`4:3`、`1:1`、`3:4`、`9:16`、`21:9`。不支持的比例必须让用户重新选择，不得擅自改成近似比例。

**自动建议默认值**（用户未指定时）：

| 创作类型 | 默认时长 | 默认比例 |
|---|---|---|
| UGC口播/带货/短视频/竖版社媒广告 | 15秒 | 9:16 |
| 短剧/剧情片/MV/电影感叙事 | 30秒 | 16:9 |
| TVC/品牌片/企业宣传片 | 30秒 | 16:9 |
| 超宽银幕电影预告/史诗叙事 | 30秒 | 21:9 |
| 教学/讲解/操作教程 | 30秒 | 16:9 |
| 方形社媒内容 | 15秒 | 1:1 |

自动建议不是用户确认，必须等待用户明确同意后才能生成。

### 1.5 调用前自检

调用视频工具前逐项确认：
- [ ] `model_version` 精确等于 `seedance_2.5`
- [ ] 工具 `prompt` 与用户确认的原文逐字一致
- [ ] 时长是 5-30 范围内的整数秒
- [ ] 比例精确等于 6 种支持值中的一个
- [ ] 时长、比例、参考素材均已获得用户明确确认
- [ ] 所有其他信息均位于独立工具参数中，没有污染 prompt

任一项不满足时，不得调用视频生成工具。

## 二、台词写入提示词规则

### 2.1 核心原则

**所有角色对话、内心独白、画外音、旁白，必须直接写进视频生成提示词中**，让AI视频模型直接生成带语音的视频。**不使用TTS（文本转语音）单独合成语音，不在后期单独做语音合成。**

AI视频模型（如Seedance 2.5）具备生成带语音视频的能力，只要在提示词中明确写出台词内容和说话角色，模型会自动生成对应的角色语音。

### 2.2 提示词中写台词的格式

| 台词类型 | 提示词中的写法 | 示例 |
|---|---|---|
| 角色对话 | `角色名说："台词内容"` | `李明说："你终于来了。"` |
| 多角色对话 | `角色A说："..."，角色B说："..."` | `李明说："你好。"，王芳说："好久不见。"` |
| 内心独白 | `角色名内心独白："..."` 或 `角色名OS："..."` | `李明内心独白："她为什么会在这里？"` |
| 画外音 | `画外音："..."` 或 `旁白："..."` | `画外音："三年后，一切都变了。"` |
| 呐喊/嘶吼 | `角色名大喊："..."` | `李明大喊："不——！"` |
| 低语/耳语 | `角色名低声说："..."` | `李明低声说："别出声。"` |

### 2.3 写台词的注意事项

- **台词必须完整写入**：不能只写"角色A说话"或"角色A与角色B对话"，必须写出具体台词内容
- **标注说话角色**：每句台词前必须标注是谁在说，避免模型混淆
- **台词用双引号**：台词内容用中文双引号`""`包裹，与提示词其他内容区分
- **情绪标注**：可以在角色名后标注情绪（如`李明愤怒地说："..."`），帮助模型生成对应语气的语音
- **长台词拆分**：单镜台词不宜过长（建议不超过30字），长台词应在分镜阶段拆分到多镜
- **内心独白/画外音也要写**：不能只写现场对话，内心独白和画外音同样要写进提示词
- **不要用TTS补救**：如果生成的视频没有语音或语音不清，检查提示词中台词是否写清楚，调整后重新生成，而不是用TTS单独合成

### 2.4 提示词中台词的位置

台词应写在提示词的**画面描述之后**，作为画面内容的一部分。示例：

```
中景，李明站在窗前，背影对着镜头，窗外是雨夜。
李明说："你终于来了。"
王芳从门口走进来，说："我知道你会等我。"
```

不要把台词单独列在提示词末尾或开头，要融入画面描述中，让模型理解台词与画面动作的对应关系。

### 2.5 生成后检查语音

视频生成后，预览时必须检查：
- 有台词的镜头是否有角色语音（不是只有BGM）
- 语音内容是否与提示词中写的台词一致
- 语音是否清晰可辨
- 多角色对话时，不同角色的声音是否有区分

如果语音缺失或不清：
1. 检查提示词中台词是否完整写出、是否标注了说话角色
2. 调整台词写法（更明确地标注角色和情绪）后重新生成
3. 不要用TTS单独合成语音来补救

## 三、生成前展示提示词 + 强制图片参考

### 3.1 生成前必须展示完整提示词

**每次调用视频生成工具前，必须用代码块把完整详细的提示词展示给用户看**，用户确认后才生成。不允许跳过提示词展示直接生成。

**展示格式**：
```
【生成前确认 — 镜头XX】
模型：seedance_2.5
模式：图生视频（带参考图）
时长：XX秒
比例：XX:XX
参考图：@图片1（角色A）、@图片2（角色B）

完整提示词：
```
[此处粘贴完整提示词，包含画面描述/人物@艾特/台词/运镜/光影]
```

是否按以上提示词生成？回复"确认"开始生成，或指出需要修改的地方。
```

**展示要求**：
- 提示词必须完整，不能省略、不能只给摘要
- 用代码块包裹，方便用户复制
- 明确标注模型、模式、时长、比例、参考图
- 用户明确确认（"确认""可以""生成"）后才调用生成工具
- 用户提出修改时，修改后重新展示完整提示词，再次确认

### 3.2 强制图生视频，禁止纯文字生成

**每次生成必须使用图生视频模式（带参考图），绝对不允许纯文字生成（文生视频）。**

- 用户提供的人物图片必须作为参考图传入视频生成工具
- 提示词中必须用`@图片N`格式艾特对应的人物
- 即使是场景空镜/过渡镜，也应使用场景参考图或前一镜末帧作为参考
- 禁止以"没有合适参考图"为由使用纯文字生成——没有参考图时用前一镜末帧或场景图

### 3.3 人物图片一人一角色，不得重复

- 用户提供的每个人物图片只对应剧中一个角色
- 同一张参考图不得用于两个不同角色
- 多余角色（无参考图的）只用纯文字描述外貌，不@任何图片
- 生成前建立角色-参考图对应表，全剧保持一致
- 详细规则见 [03-prompt-generation.md](03-prompt-generation.md) 第3.2节

## 四、生成任务卡

### 1.1 每镜建立任务卡

生成前，为每个镜头建立独立的任务卡，记录所有生成参数和状态。

```
【镜头任务卡】
镜号：01
所属场景：场景A
分镜组：分组1
优先级：P0/P1/P2
生成引擎：seedance_2.5（默认）/ 即梦 / MiniMax
Prompt：[完整提示词，原文透传，有台词必须写进提示词]
是否有台词：是/否（有台词时提示词中必须包含角色台词）
参考图：@图片1（角色锚定）、@图片2（场景参考）
生成模式：文生视频/图生视频
画幅：9:16/16:9/21:9/4:3/1:1/3:4
时长：X秒（5-30整数）
依赖：无/依赖镜XX的末帧
状态：待生成/待用户确认/生成中/已完成/待预览确认/需重试/已废弃
版本：v1/v2/v3
预览播放器：[内嵌预览播放器交付状态]
生成结果链接：[公共访问链接]
用户确认：未确认/已确认通过/需修改
问题记录：[如有问题，记录问题类型和严重度]
```

### 1.2 优先级分级

| 优先级 | 定义 | 处理顺序 |
|---|---|---|
| P0 | 反转镜、高潮镜、结尾悬念镜、开场钩子镜 | 最先生成，优先重试，最多3次 |
| P1 | 核心冲突推进镜、关键对白镜、情绪爆发镜 | 第二批生成，最多2次 |
| P2 | 过渡镜、空镜、反应镜、环境镜 | 最后生成，1次即可，不合格可后期修复 |

**原则**：P0镜头质量直接决定全片成败，必须投入最多资源；P2镜头可以接受瑕疵，用后期弥补。

## 五、批次策略

### 2.1 按场景分组

- 同一场景的镜头放在同一批次生成
- 单批≤6个镜头（避免批量生成时质量下降）
- 超过6镜的场景拆分为多批
- 不同场景的镜头不要混在一批（场景风格差异会影响生成质量）

### 2.2 批次内顺序

同一批次内，按以下顺序生成：
1. 先生成P0镜头（反转/高潮/悬念）
2. 再生成P1镜头（核心冲突/关键对白）
3. 最后生成P2镜头（过渡/空镜/反应）

### 2.3 批次间衔接

- 前一批次完成后，检查质量，确认无重大问题后再开始下一批
- 连续镜头（镜A→镜B）：镜B的首帧参考镜A的末帧
- 如果镜A质量不合格，先修复镜A再生成镜B（避免错误传递）

## 六、连续镜首帧处理

### 3.1 首帧参考策略

对于连续的两个镜头（镜A→镜B），为了保证视觉连贯性：

- **镜B的首帧**：使用镜A的末帧作为参考图（图生视频模式）
- **镜B的Prompt**：在Prompt中描述"从[镜A末帧状态]开始，[镜B的动作]"
- **光线/场景**：镜B的光线和场景描述必须与镜A一致

### 3.2 首帧参考的适用场景

| 场景 | 是否用首帧参考 | 原因 |
|---|---|---|
| 同场景连续动作 | ✅ 是 | 保证动作连贯、空间连续 |
| 同场景对话正反打 | ✅ 是 | 保证光线、空间一致 |
| 同场景但时间跳转（如"一小时后"） | ⚠️ 可选 | 光线可能变化，可调整 |
| 不同场景切换 | ❌ 否 | 场景不同，不需要连续 |
| 蒙太奇快切 | ❌ 否 | 刻意不连续，制造节奏 |

### 3.3 首帧参考操作

1. 生成镜A，获取镜A的视频文件
2. 截取镜A的最后一帧（末帧）作为图片
3. 上传末帧图片，获取公共访问链接
4. 生成镜B时，使用图生视频模式，首帧参考图=镜A末帧
5. 在Prompt中描述从末帧状态开始的动作

## 七、重试与版本管理

### 4.1 重试触发条件

生成完成后，立即审核（见模块5质量审核）。以下情况需要重试：
- 面部崩坏（换脸/五官扭曲/多余手指）
- 场景跑偏（与Prompt描述的场景不符）
- 动作完全错误（与Prompt描述的动作不符）
- 光影异常（无来源光/过曝/全黑）
- 合规问题（出现血液/暴力/违规内容）
- 时长严重不符（生成时长与目标差>20%）

以下情况不需要重试（可后期修复）：
- 轻微动作卡顿
- 光影小差异
- 背景细节模糊
- 轻微色彩偏差

### 4.2 重试次数上限

| 优先级 | 最大重试次数 | 超过后处理 |
|---|---|---|
| P0 | 3次 | 导演决策（重新设计镜头/用替代镜头） |
| P1 | 2次 | 导演决策（调整Prompt/换景别/用替代镜头） |
| P2 | 1次 | 接受当前版本，后期修复 |

**铁律**：同一镜头重试不超过3次。3次仍不合格，停止重试，进入导演决策流程（见模块7），不要无限重试浪费资源。

### 4.3 重试时的Prompt调整

每次重试，必须调整Prompt，不能用完全相同的Prompt重新生成：

- **第1次重试**：微调Prompt（增加细节描述/调整光线/明确动作）
- **第2次重试**：较大调整（换景别/换机位角度/简化动作/增加参考图）
- **第3次重试**：根本性调整（拆分镜头/用替代镜头/改变调度，见模块7导演决策）

### 4.4 版本命名与管理

- 每个镜头的每个版本独立保存，不覆盖
- 命名格式：`镜号_版本号.mp4`（如`01_v1.mp4`、`01_v2.mp4`）
- 每个版本都必须上传并提供公共访问链接
- 终选版本标记为`final`（如`01_final.mp4`）
- 保留所有历史版本，便于对比和回退

**版本记录表**：
```
镜号 | 版本 | 生成时间 | Prompt版本 | 问题记录 | 状态
01   | v1   | 09-07 14:00 | Prompt v1 | 面部微崩坏 | 废弃
01   | v2   | 09-07 14:05 | Prompt v2 | 动作略卡 | 备选
01   | v3   | 09-07 14:10 | Prompt v3 | 合格 | 终选(final)
```

## 九、内嵌预览播放器交付 + 公共访问链接（全局铁律）

### 7.1 铁律内容

**每生成完一个视频（包括单镜片段、九宫格成图、最终成片），必须以内嵌预览播放器形式展示在聊天对话中**，用户可直接点击播放按钮预览播放（类似视频消息卡片，内嵌在聊天界面里，无需跳转外部页面）。同时附公共访问链接作为补充。

**两条交付要求缺一不可**：
1. ✅ 内嵌预览播放器（首选，用户直接在聊天里点播放）
2. ✅ 公共访问链接（补充，用户可下载/分享）

### 7.2 执行流程

```
视频生成完成
    │
    ▼
获取视频文件（本地路径或平台返回的临时链接）
    │
    ▼
上传至可公共访问的文件存储（FileBatchUpload工具）
    │
    ▼
获取公共访问URL
    │
    ▼
以内嵌预览播放器形式展示视频（用户可直接在聊天中点击播放）
    │
    ▼
同时附公共访问链接（文字链接形式）
    │
    ▼
停下等待用户预览确认（"可以/继续/通过"）
    │
    ▼
用户确认后，再生成下一条视频
    │
    ▼
将链接记录到版本记录表和生成进度表
```

### 7.3 交付格式

**单镜生成完成时**：
```
【镜头01 v1 生成完成】
[内嵌预览播放器 — 用户可直接点击播放]

问题：面部微崩坏（中度），建议重试
公共链接：[点击下载镜头01 v1](https://...)

请预览后确认是否通过，或指出需要修改的地方。确认后回复"继续"生成下一条。
```

**批次完成时**：
```
【场景A 批次1 完成（3/6镜）】

镜01 v3(final) ✅
[内嵌预览播放器]
公共链接：[点击下载](https://...)

镜02 v1(final) ✅
[内嵌预览播放器]
公共链接：[点击下载](https://...)

镜03 v2 🔄（动作略卡，待决定是否重试）
[内嵌预览播放器]
公共链接：[点击下载](https://...)

请逐条预览确认，全部通过后回复"继续"生成下一批。
```

**全部完成时**：
```
【全片生成完成】
共XX镜，合格XX镜，需后期修复XX镜

所有终选版本：
镜01 [内嵌预览播放器] 链接：...
镜02 [内嵌预览播放器] 链接：...
...
```

### 7.4 用户预览确认协议

- **每条视频生成后必须停下**，等待用户预览并明确确认
- 用户确认方式：回复"可以""继续""通过""OK"等明确肯定
- 用户未确认前，**不得继续生成后续镜头**
- 用户提出修改意见时，按意见调整后重新生成，重新交付预览
- 用户要求跳过某条时，记录原因后继续下一条
- 批量生成时，每批完成后停下等待用户确认该批，再继续下一批

### 7.5 禁止事项

- ❌ 只说"已生成"不给预览播放器
- ❌ 只给公共链接，不给内嵌预览播放器
- ❌ 只给本地文件路径
- ❌ 生成后不等待用户确认，直接继续生成下一条
- ❌ 链接失效或无法访问
- ❌ 成片和片段只给一个链接（每个版本都要给预览+链接）
- ❌ 生成后忘记上传，过了临时链接有效期才发现

## 十、即梦平台批量操作指南

### 7.1 图生视频参数设置

- 首帧图：上传角色锚定图或前一镜末帧
- 提示词：粘贴模块3生成的Prompt
- 时长：按分镜标注的时长（5秒/10秒/15秒）
- 画幅：9:16（竖屏）或16:9（横屏）
- 运动强度：文戏=低/中，武戏=中/高
- 参考图权重：角色一致性要求高时调高（0.7-0.8），动作自由度要求高时调低（0.4-0.5）

### 7.2 文生视频参数设置

- 提示词：粘贴模块3生成的Prompt
- 时长：按分镜标注
- 画幅：9:16或16:9
- 运动强度：按场景类型
- 负面提示词：粘贴模块3生成的负向提示

### 7.3 批量生成管理

- 不要一次性提交超过6个生成任务（平台可能限流或质量下降）
- 每批生成完成后，下载所有视频，上传获取公共链接，审核质量
- 合格的标记final，不合格的进入重试流程
- 保持生成任务的有序性，不要混乱提交

## 十一、视频生成执行自检门

- [ ] 是否默认使用 Seedance 2.5 引擎（model_version=seedance_2.5）？

- [ ] **用户是否明确确认提示词后才调用生成工具？**
- [ ] 生成前是否向用户展示了完整确认信息（模型/提示词/时长/比例/参考素材）？

- [ ] 比例是否在支持的6种内（16:9/4:3/1:1/3:4/9:16/21:9）？

- [ ] 每个镜头是否都有生成任务卡？

- [ ] **用户是否预览确认后才继续生成下一条？**
- [ ] 每个视频是否同时附了公共访问链接？
- [ ] 链接是否记录到版本记录表和进度表？
