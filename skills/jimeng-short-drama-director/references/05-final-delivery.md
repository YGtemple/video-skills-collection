# 成片审核与交付规范

## 概述

本文件定义成片终审清单、多平台交付规格、导出参数和发布前最终检查。成片审核是最后一道质量门——任何在前期/中期遗漏的问题，都必须在这里被抓住。

---

## 一、成片终审清单

成片导出后，必须**完整播放至少两遍**，按以下清单逐项检查。第一遍专注画面和节奏，第二遍专注音频和字幕。

### 1.1 时长与结构

- [ ] 总时长严格90秒（±2秒），不超过92秒，不少于88秒
- [ ] 四幕时间锁命中：开场10-15秒、核心冲突40-50秒、反转15-20秒（65-80秒区间）、结尾5-10秒
- [ ] 开场3秒内有强冲击（冲突/悬念/异常）
- [ ] 反转在65-80秒区间，有前期伏笔
- [ ] 结尾有强悬念钩子，卡点准确
- [ ] 片头2-3秒，片尾悬念卡2-3秒

### 1.2 画面质量

- [ ] 全片无明显模糊、噪点、AI拼贴感
- [ ] 无面部崩坏、肢体扭曲、多余手指
- [ ] 无黑帧、跳帧、花屏
- [ ] 无画面裁切（主体不被边缘切掉）
- [ ] 无水印/平台UI残留（如果是从其他平台下载的素材）
- [ ] 画质在手机全屏播放时清晰可辨

### 1.3 角色与场景一致性

- [ ] 所有角色在全镜中面部/服装/发型一致（无换脸）
- [ ] 同场景空间布局、道具位置连续（无跳变）
- [ ] 相邻镜头光影衔接（无硬切式光源突变）
- [ ] 关键道具在各镜中位置/状态连续（无瞬移）
- [ ] 无越轴（角色左右位置不无故互换）

### 1.4 节奏与剪辑

- [ ] 剪辑节奏匹配四幕情绪曲线（开场快、推进中、反转最快、结尾放慢）
- [ ] 无过长镜头（单镜不超过8秒，除非有明确叙事目的）
- [ ] 无过短镜头（单镜不少于0.5秒，快切蒙太奇除外）
- [ ] 动作连贯（无动作截断/瞬移）
- [ ] 转场克制（默认硬切，非硬切转场有明确叙事目的）
- [ ] 反转时刻有节奏变化（骤停/加速/闪切）

### 1.5 音频质量

- [ ] 台词清晰可辨，无杂音/爆音/失真
- [ ] 音量层级正确：台词>动效>环境音>BGM
- [ ] BGM在台词出现时自动压低（Ducking）
- [ ] 动效音与画面动作精确同步（无明显时差）
- [ ] 环境音随场景变化（无场景变了环境音没变）
- [ ] 无音频断裂/爆音/静音段（除非是刻意的骤停）
- [ ] 整体响度统一（无某段突然变大/变小）
- [ ] 反转时刻有音效冲击（低音boom/骤停/爆发）

### 1.6 字幕

- [ ] 所有台词都有字幕，无遗漏
- [ ] 字幕与语音完全同步（无早于/晚于超过0.3秒）
- [ ] 字幕位置在下方安全区，不被平台UI遮挡
- [ ] 字幕颜色/描边在任何背景下都可读
- [ ] 无错别字、漏字、多字
- [ ] 重点台词强调样式不超过3-5处
- [ ] 字幕单行不超过12字（竖屏）

### 1.7 调色与视觉统一

- [ ] 全片色调统一（无跨镜色彩跳跃）
- [ ] 四幕色调微调符合情绪设计
- [ ] 肤色在全镜中一致（无偏色）
- [ ] 无过曝/欠曝区域（除非是刻意的光影设计）
- [ ] 暗角/锐化等效果统一

### 1.8 合规安全

- [ ] 全片无血腥/暴力/死亡特写
- [ ] 无敏感符号/违规文字/不当着装
- [ ] 伤害/死亡画面已通过合规替换（无血液/断肢/尸体）
- [ ] 无平台违禁内容（检查目标平台的社区规范）

### 1.9 片头片尾

- [ ] 片头剧名清晰，时长2-3秒
- [ ] 片尾悬念卡有悬念句+追更引导
- [ ] 片头→正片、正片→片尾的转场自然
- [ ] 片尾音频戛然而止（增强悬念）

## 二、终审问题处理流程

```
终审发现问题
    │
    ├─ 致命问题（影响观看/合规）→ 必须修复后重新导出
    │   ├─ 换脸/场景跳变 → 回阶段三，重生成偏差镜头
    │   ├─ 合规问题 → 立即移除/替换违规镜头
    │   ├─ 音画不同步/黑帧 → 回后期修复
    │   └─ 字幕错误 → 修正字幕后重新导出
    │
    ├─ 重要问题（影响体验但不致命）→ 评估修复成本，尽量修复
    │   ├─ 个别镜头动作略卡 → 可接受或微调
    │   ├─ 光影小差异 → 后期调色统一
    │   ├─ 动效音略不同步 → 微调时间轴
    │   └─ 节奏略拖沓 → 微调镜头时长
    │
    └─ 轻微问题（不影响观看）→ 记录，可接受
        ├─ 背景轻微变形
        ├─ 个别帧轻微噪点
        └─ 字幕停留时间略长/略短
```

**原则**：致命问题零容忍，必须修复；重要问题尽量修复；轻微问题可以接受，不要为了完美无限延期。

## 三、多平台交付规格

### 3.1 抖音 / 快手（竖屏短剧主阵地）

| 参数 | 规格 |
|---|---|
| 画幅 | 9:16（竖屏） |
| 分辨率 | 1080×1920（最低），推荐1080×1920或更高 |
| 帧率 | 30fps（推荐），60fps（高动态场景） |
| 编码 | H.264（AVC），High Profile |
| 码率 | ≥8Mbps（1080p），≥12Mbps（如果源素材质量高） |
| 音频 | AAC，320kbps，48kHz，立体声 |
| 文件大小 | ≤500MB |
| 时长 | ≤90秒（短剧第1集），单条最长15分钟（合集） |
| 封面 | 9:16，1080×1920，JPG/PNG，文件≤5MB |

**抖音特别注意**：
- 上传时选择"高清发布"，避免平台二次压缩
- 封面图要在第一帧就有冲击力（用户在feed中看到的是封面）
- 标题/话题标签在发布时添加，不烧录在视频中

### 3.2 B站 / 视频号（支持横竖屏）

| 参数 | 规格 |
|---|---|
| 画幅 | 9:16（竖屏）或16:9（横屏） |
| 分辨率 | 1080p（1920×1080或1080×1920） |
| 帧率 | 30fps |
| 编码 | H.264 |
| 码率 | ≥8Mbps |
| 音频 | AAC，320kbps |
| 文件大小 | B站≤8GB，视频号≤2GB |
| 封面 | B站16:9（1920×1080），视频号支持多种比例 |

**B站特别注意**：
- B站用户对画质敏感，尽量用高码率
- 可以加CC字幕（SRT文件），不一定要烧录
- 标题和简介要详细，B站用户会看简介

### 3.3 小红书

| 参数 | 规格 |
|---|---|
| 画幅 | 9:16（竖屏）或3:4（竖版图文视频） |
| 分辨率 | 1080×1920（9:16）或1080×1440（3:4） |
| 帧率 | 30fps |
| 编码 | H.264 |
| 时长 | ≤5分钟（短剧90秒完全没问题） |
| 文件大小 | 建议≤200MB |
| 封面 | 3:4（1080×1440）效果最好，小红书feed是3:4 |

**小红书特别注意**：
- 小红书的feed是3:4比例，9:16视频会被裁切显示，重要内容要放在中间3:4安全区
- 封面图要有文字标题（小红书用户习惯看封面文字）
- 话题标签很重要，发布时添加

### 3.4 通用导出参数（推荐）

如果只导出一个版本用于多平台，用以下参数：

```
容器：MP4
视频编码：H.264（AVC），High Profile，Level 4.1
分辨率：1080×1920（9:16竖屏）
帧率：30fps
码率：10Mbps（VBR，最大12Mbps）
关键帧间隔：2秒（60帧）
B帧：3
音频编码：AAC-LC
音频码率：320kbps
音频采样率：48kHz
音频声道：立体声
```

## 四、封面图设计规范

### 4.1 封面图要求

- **尺寸**：9:16（1080×1920）用于抖音/快手；3:4（1080×1440）用于小红书；16:9（1920×1080）用于B站
- **格式**：JPG（质量≥90%）或PNG
- **文件大小**：≤5MB
- **文字安全区**：重要文字放在画面中间60%区域，避免被平台UI遮挡

### 4.2 封面图设计要点

- **第一视觉**：选全剧最有冲击力的画面（反转镜/高潮镜/角色特写）
- **标题文字**：加剧名（大字）+ 悬念句（小字），字体清晰
- **人物**：如果是角色驱动的短剧，封面要有角色面部（观众认人）
- **色调**：与全片色调一致，不要用与正片完全不同的滤镜
- **不要**：不要用模糊截图、不要加太多文字（不超过3行）、不要用与内容无关的图

### 4.3 封面图文字模板

```
【大字】剧名（如：《午夜来电》）
【中字】悬念句（如："她已经死了三年"）
【小字】集数/标签（如：第1集 · 悬疑反转）
```

## 五、文件命名与版本管理

### 5.1 文件命名规范

```
剧名_集数_版本_日期_平台.mp4

示例：
wuyedianlai_01_v1_20260907_douyin.mp4
wuyedianlai_01_v2_final_20260907_all.mp4
```

- 剧名：英文或拼音，无空格
- 集数：两位数（01、02）
- 版本：v1/v2/v3，终选版加final
- 日期：YYYYMMDD
- 平台：douyin/kuaishou/bilibili/xiaohongshu/all（通用版）

### 5.2 版本管理

- 保留所有历史版本（不要覆盖）
- 终选版本单独标记（加final后缀）
- 每个版本记录修改内容（在文件名或单独的changelog中）
- 发布后保留最终发布版本（不要修改已发布的文件，如需修改用新版本号）

## 六、发布前最终检查

发布前最后一遍检查（在手机上检查，因为用户主要在手机上看）：

- [ ] 在手机上完整播放一遍，确认画质/音质在手机上正常
- [ ] 字幕在手机上清晰可读（不要在电脑上觉得OK就过了，手机屏幕小）
- [ ] 封面图在平台feed中显示正常（文字不被裁切）
- [ ] 标题/话题标签已准备好
- [ ] 视频文件已上传至平台，平台转码后预览正常
- [ ] 发布时间选择流量高峰（抖音/快手：12:00-13:00，18:00-22:00；小红书：12:00-14:00，20:00-22:00）
- [ ] 已准备好发布后的互动话术（回复评论、引导追更）

## 七、交付物清单

最终交付给用户的文件包括：

| 文件 | 说明 | 格式 |
|---|---|---|
| 成片视频 | 最终合成的90秒短剧 | MP4（H.264，1080×1920，30fps） |
| 封面图 | 平台发布用封面 | JPG/PNG（9:16或3:4） |
| 字幕文件 | 独立字幕（可选，B站等支持CC字幕的平台） | SRT |
| 分镜表 | 最终版分镜（含镜号/时长/景别/动作） | Markdown/PDF |
| 审核报告 | 逐镜审核+一致性检查+终审报告 | Markdown/PDF |

**交付说明**：写明每个文件的用途、目标平台、发布注意事项。
