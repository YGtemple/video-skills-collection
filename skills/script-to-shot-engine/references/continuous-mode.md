# 连续多 Clip 模式

## 触发条件

满足以下任一条件时使用：

- 总时长超过用户或模型的单次上限。
- 用户要求完整长打戏、多段提示词或跨场景战斗。
- 单段无法清楚承载主要动作因果。
- 武器、伤势、优势、人物目标或场景区域发生重大变化。

不要机械地每 15 秒切一刀。先设计完整局势变化，再在完整动作结果处拆分。

## 拆分位置

优先在以下节点结束 Clip：

- 一次攻防已经产生明确结果。
- 人物到达新的空间区域。
- 武器完成夺取、丢失、断裂或更换。
- 一方完成脱困、压制或优势反转。
- 门、墙、烟尘、掠过前景等自然遮挡提供衔接点。

不要在以下状态中间结束：

- 攻击已经发起但尚未命中或避开。
- 抓抱、夺取武器或换弹仍未完成。
- 人物仍在半空且落点不明。
- 法术或爆炸已经释放但结果尚未出现。

## 最小连续性

内部只维护对下一段有用的信息：

- 人物所在区域和大致面向。
- 武器由谁持有以及哪只手。
- 持续伤势、服装或武器变化。
- 关键敌人的局部状态。
- 已发生的场景破坏。
- 下一段摄影机从哪一侧继续。

不要生成完整坐标、全量状态 JSON 或角色逐帧位置表。

## 提示词交接

承接信息不单独成行，直接写进下一段「空间站位」的开头，以「承接上一段，」起句；结尾信息写入「结尾状态」。下一段必须从上一段结尾状态的事实开始，但可以改写句式。不要把上一段完整 Prompt 复制到下一段。示例见 examples/continuous-fight.md 的实际用法。

## 全场输出

- 全场只输出一次美术资产对照卡。
- 每个 Clip 仍须独立可投喂，因此重复该 Clip 实际使用资产的短锚点。
- 全局视觉风格可以在每个 Clip 开头用一句短语重申，不复制长篇风格说明。
- 每个 Clip 只写一次空间站位；随后逐镜头给出各自的时间范围、光圈（附景深描述）、焦段（附景别描述）、机位/运镜（专业术语附英文）和动作结果。
- 每个 Clip 的时间戳独立从 0 秒开始，连续覆盖到该 Clip 自己的总时长，不使用跨 Clip 的累计时间。
- 每个完整 15 秒逐镜头 Clip 遵循主执行文件的镜头下限；不足 15 秒的尾段按动作完整性安排镜头，不强行凑到 10 个。
- 生成前提醒集中放在全部 Clip 之后，最多三条。
