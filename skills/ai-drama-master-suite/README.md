# ai-drama-master-suite 仓库说明文档

> 一句话简介：AI 短剧全链路制作技能套件，剧本到成片八大模块与 40 条全局铁律

## 一、项目概述与定位

`ai-drama-master-suite`（AI 短剧全能大师）是一套面向 **AI 短剧 / 动态漫 / 剧情类视频**创作的**全流程工作流规范（AI Agent Skill）**。它把"从一个想法到成片交付"的完整链路标准化为八大模块，可直接作为 AI 编程/创作智能体的技能包加载，也可作为人工创作手册阅读。

- **形态**：不是可运行程序，而是一套 Markdown 规范集——主入口 `SKILL.md`（含 YAML frontmatter：`name` + `description`）+ `references/` 下 33 个专题文档；
- **全链路**：想法 → 剧本 → 分镜 → 提示词 → 视频片段 → 审核 → 硬拼接成片，环环相扣；
- **经验沉淀**：基于多个真实短剧项目（如《斗罗·六子觉醒》56 镜）实战总结，所有规范经实际生成验证；
- **整合地位**：v2.0.0 起整合原 `video-master-suite`，成为唯一统一的视频/短剧技能入口。

设计信条：「镜头服务叙事，不为炫技」「每一个交付物必须可直接使用」。

## 三、主入口 SKILL.md 的工作机制

`SKILL.md` 是被 AI Agent 自动加载的总调度文件，结构如下：

1. **YAML frontmatter**：`name` + 一段极长的 `description`，用于技能自动触发匹配（涵盖八大模块能力与全局铁律摘要）；
2. **接手总指导（权威导读）**：告诉接手的 AI ①每次必读 SKILL.md；②按"用户给了什么"判入口；③阅读路线图（阶段→按序读哪些文件→产出→过确认门）；④按题材选默认方法论公式；⑤确认门节奏；⑥改完同步文档；
3. **技能扩展规范**：规定日后加新文件的编号续排规则、分组（A 组 01-07 流程规范、B 组 08 案例、C 组 09+ 方法论）、"加新文件必做四件事"；
4. **全流程工作顺序 + 各阶段必读文件速查表**；
5. **强制必读清单（P0/P1 分级）**：P0 每次必查（SKILL.md、16 项目启动、14 视觉术语、13 封面），P1 进入对应模块必读；
6. **全局铁律 0–39**；
7. **参考文件索引**。

**入口路由（按用户输入切入）**：只有想法→模块1 剧本；已有剧本→模块2 分镜；已有分镜→模块3 提示词；已有提示词要批量出片→模块4 生成；已有片段要审/修→模块5；镜头确认要合成→模块6 硬拼接；要封面/交付→模块7；从 0 到 1 全包则 1→7 顺序走；非短剧类（商业视频/素材处理/在线提取/音频/图片资产）→路由到 23 号文件指向的其他子技能。

## 五、全局铁律（0–39 概览）

铁律是所有模块必须遵守的硬约束，关键者包括：

- **引擎**：Seedance 2.5 为最高优先级默认引擎，`model_version=seedance_2.5`，最终提示词逐字原文透传不改写（铁律 0）；时长 5–30 秒，比例 16:9/4:3/1:1/3:4/9:16/21:9；
- **交付形态**：每镜以内嵌预览播放器交付并附公共链接；每次生成先完整展示提示词、展示提示词的同时直接出片（不停下等待确认），成片+完整脚本/提示词一起必看，模块之间需用户确认（铁律 1/5/8）；
- **不做去水印、合规安全**（铁律 2/3）；
- **物理可行性优先**：室内小空间禁大远景/升降等（铁律 4）；
- **台词/环境音写进提示词、不用 TTS、不混入人为配乐 BGM**（铁律 7/26）；
- **强制图生视频 + `@图片N` 艾特人物，一人一角色不重复**（铁律 8/9）；
- **节奏**：每 3–4 秒一个信息点、开局前 3 秒强钩子且扎根剧本、全片持续爆点（铁律 11/18/23）；
- **立人方式**：靠剧情行动而非旁白，画面表演为主旁白为辅（铁律 14/17）；
- **一致性**：站位三要素写进提示词、面部不崩 + 服装同阶段锁死（铁律 16/24）；多段同场景跨段锁场景用 24 号机位底图锁定法；
- **默认横屏 16:9**、全片零字幕、封面电影海报级（铁律 13/19/20/22）；
- **硬拼接不压缩画质、H.264+AAC 兼容封装、流拷贝优先**（铁律 25）；**文件按内容命名（4–20 字、见名知意、带镜头/段落编号，禁空泛名）**；**段间必做衔接（铁律 31）、废片留存归档不删除、铁律 32 交付前 ffprobe 必检 H.264+AAC/faststart**；用户满意后主动提醒沉淀经验（铁律 21）；
- **站位稳定**：人物站位正常、跨镜连贯，不瞬移、不无故互换、不越轴、不穿模，异常按 P0 重生成（铁律 27）。
- **美术资产 AI 可直接生成、出图必审通过才定稿 @（用户自制可选）**：角色/场景/道具/关键画面参考图 AI 可直接调用文生图，每张/批出图即交付用户审核，通过才定稿 @（铁律 28）。
- **先完整展示提示词、展示同时直接出片，成片+完整脚本/提示词必看、用户认可才下一个；成片必查字幕/穿模**：展示提示词的同时直接生成（不停下等待确认），逐个生成逐个审核，禁止未经认可连续批量自动出片；成片逐镜自检意外文字/穿模畸形并复核脸/服装/站位/轴线/音画同步（铁律 8/29）。
- **不出关键帧**：不主动为每镜新做「关键帧/定帧图/首帧图/尾帧图」静态图、不设「先出关键帧再图生视频」环节；直接用已审核美术资产（角色/场景/道具/机位底图）＋视频提示词生成；视频模型要挂参考图时复用已审核资产图/机位底图或前一镜已生成末帧，仅用户明确点名某帧时才按需产出（铁律 30）。分镜参考图/调度图/资产图/机位底图照常保留。跨组技术全景锚点（33号）即“复用已生成视频末帧做链式衔接”的标准化版本：模式A在组尾追加1秒并在拼前剔除，模式B在正片完成后另生成5秒技术补段且不进filelist；两种模式均不算新做关键帧成品。
- **进资产环节前必读资产大师**：进入任何资产环节前必须完整 Read `script-asset-master` 的 SKILL.md，不得跳过、不得凭印象执行（铁律 33）。
- **常规交付两件、MJ 按需**：常规只主导交付①立项大纲＋②通用模型资产提示词；③MJ 提示词仅用户明确点名「MJ / Midjourney」时才产出（铁律 34）。
- **项目目录统一**：本地项目统一放 `D:\豆包产物\短剧项目\<按内容命名>\`，含 `01_剧本`/`02_资产`/`03_分镜`/`04_视频`/`05_成片`/`06_封面` 六个子文件夹并按类归位（铁律 35）。
- **分镜组默认 30 秒**：对齐模型单次 30s 上限，内容需要更短时灵活缩短（铁律 36）。
- **文件命名**：按内容命名、4–20 字、见名知意、带编号，禁空泛名（铁律 37）。
- **复刻重制＋高还原**：复刻必须启动 script-asset-master、全部美术资产重新制作不搬运，场景/剧情顺序/台词/人物站位/机位逐镜对齐原片、不自由改编（铁律 38）。
- **资产三维必标**：每条资产提示词旁必标风格化/怪异度/多样性取值及理由（MJ 对应 `--stylize`/`--weird`/`--chaos`/`--seed`），写实默认低/低/低＋固定 seed（铁律 39）。

## 七、跨任务路由（references/23）

该文件把本技能从"只做短剧"扩展为统一的视频/视频任务入口，识别 6 大任务类型并路由：

- **A 短剧/剧情片** → 走本技能模块 1→7；
- **B 商业视频/广告/UGC** → 路由到 `doubao-creative-video` + seedance/image_to_video 等生成工具；
- **C 已有素材后期/剪辑/增强** → `byted-mediakit-editing` / `byted-mediakit-video` / `jianying-editor`（附工具决策树）；
- **D 在线视频提取/转写/理解** → `doubao-video-extract`；
- **E 音频制作处理** → `seed-audio` / `byted-mediakit-audio`；
- **F 图片资产生成/处理** → `doubao-creative-design` / `seedream-50` / `script-asset-master` 等。

并强调：短剧模块6 的"硬拼接"不等于任务 C 的精剪——后期剪辑/调色/配乐一律用户自理。

## 八、技术栈与使用方式

- **纯 Markdown 技能包**：无代码、无构建；靠 frontmatter 让 AI Agent 自动识别；
- **使用方式**：克隆到 Skills 目录后由支持 Skill 的 AI 环境加载；或人工从 `SKILL.md` 按阅读路线图顺序阅读；
- **实战配套**：视频生成对接 Seedance 2.5 等引擎，硬拼接用 ffmpeg concat demuxer / `-c copy` 流拷贝；
- **许可证**：MIT。
