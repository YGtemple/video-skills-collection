# 视频生成执行规范

## 概述

将提示词转化为实际的AI视频片段。本模块负责批量生成调度、任务管理、重试策略、版本管理。**三条最高优先级铁律**：
1. **Seedance 2.5 为默认且最高优先级视频生成引擎**，提示词原文透传不改写；每次生成先完整展示提示词、展示提示词的同时直接生成（不停下等待确认），成片后把完整提示词随成片一起交付审核，用户可随时插话修改
2. **有台词必须写进提示词**，让AI模型直接生成带语音的视频，不使用TTS单独合成
3. **每生成完一个视频必须以内嵌预览播放器形式交付**（用户可直接在聊天中点击播放预览），并把「成片（内嵌预览）+ 该视频完整脚本/分镜 + 完整视频提示词（@已审核资产）」一起给用户看；**用户认可这个成片后才生成下一个**，逐个生成、逐个审核，禁止未经认可连续批量自动出全部片段，同时附公共访问链接
4. **不用终端**：全流程在对话界面完成，所有生成、预览、交付通过对话内工具调用和 present_files 完成，不需要用户进行任何命令行/终端操作。

## 一、Seedance 2.5 最高优先级引擎

### 1.1 引擎优先级

| 优先级 | 引擎 | 适用场景 |
|---|---|---|
| ⭐ 最高（默认） | **Seedance 2.5** | 所有视频生成的默认选择，除非用户明确指定其他引擎 |
| 备选 | 即梦（横屏电影/竖屏Seedance/通用竖屏） | 用户明确要求即梦平台，或需要即梦特定风格引擎时 |
| 备选 | MiniMax H3 | 用户明确要求MiniMax平台时 |

**铁律**：默认使用 Seedance 2.5，不得因画质判断/速度/成本/时长或其他偏好自动切换到其他模型。仅当用户明确指定其他引擎时才切换。

### 1.2 原文透传规则

用户确认的最终视频提示词必须**逐字原文透传**给视频生成工具，具体要求：
- 不扩写、润色、精简、翻译、纠错或重排
- 不增加标题、前缀、后缀、负面提示词、镜头说明、风格词、质量词或结构化模板
- 不改变标点、空格、换行、大小写、语言、数字、符号或拼写
- 不把参考素材说明、工具参数、确认摘要或系统说明拼接进 prompt
- 不从聊天中的其他文字推断并补写 prompt

若用户要求修改提示词，先让用户提供或确认修改后的最终版本；得到最终版本后，仍按原文透传。

### 1.3 生成后随成片展示完整信息（必须执行）

**每次生成视频先完整展示提示词、展示提示词的同时直接生成（不停下等待确认）。成片生成后**，必须把「成片 + 完整信息 + 完整提示词」一起给用户看。展示信息至少包括：

```
【生成后交付 — 镜头XX】
[内嵌预览播放器：该镜头成片]
模型：seedance_2.5（固定）
任务类型：图生视频
原始 prompt：
```
[完整提示词，逐字展示，保留原有换行和符号]
```
时长：XX秒
比例：XX:XX
参考素材：@图片N 对应角色
完整脚本/分镜：[该镜头脚本/分镜]
```

成片连同完整脚本/分镜、完整提示词一起给用户看后，**等用户认可这个成片才生成下一个**；用户觉得不合适则按意见改提示词/重生成该视频、再审通过才往下。用户可随时插话提出修改意见。

### 1.4 时长与比例限制

**时长**：Seedance 2.5 支持整数 5-30 秒。超出范围时请用户改选时长，不得切换模型。

**比例**：仅支持以下 6 个精确值：`16:9`、`4:3`、`1:1`、`3:4`、`9:16`、`21:9`。不支持的比例必须让用户重新选择，不得擅自改成近似比例。

**自动建议默认值**（用户未指定时）：

| 创作类型 | 默认时长 | 默认比例 |
|---|---|---|
| UGC口播/带货/短视频/竖版社媒广告 | 15秒 | 9:16 |
| 短剧/剧情片/MV/电影感叙事 | 30秒 | 16:9 |
| TVC/品牌片/企业宣传片 | 30秒 | 16:9 |
| 超宽银幕电影预告/史诗叙事 | 30秒 | 21:9 |
| 教学/讲解/操作教程 | 30秒 | 16:9 |
| 方形社媒内容 | 15秒 | 1:1 |

自动建议默认值直接使用，在生成后随成片交付时注明（提示词完整透明，不省略）。

### 1.5 调用前自检

调用视频工具前逐项确认：
- [ ] `model_version` 精确等于 `seedance_2.5`
- [ ] 工具 `prompt` 原文透传（逐字、未改写/润色/加负面词）
- [ ] 时长是 5-30 范围内的整数秒
- [ ] 比例精确等于 6 种支持值中的一个
- [ ] 时长、比例、参考素材已备好，生成后随成片完整透明展示
- [ ] 所有其他信息均位于独立工具参数中，没有污染 prompt

任一项不满足时，不得调用视频生成工具。

## 二、台词写入提示词规则

### 2.1 核心原则

**所有角色对话、内心独白、画外音、旁白，必须直接写进视频生成提示词中**，让AI视频模型直接生成带语音的视频。**不使用TTS（文本转语音）单独合成语音，不在后期单独做语音合成。**

AI视频模型（如Seedance 2.5）具备生成带语音视频的能力，只要在提示词中明确写出台词内容和说话角色，模型会自动生成对应的角色语音。

### 2.2 提示词中写台词的格式

| 台词类型 | 提示词中的写法 | 示例 |
|---|---|---|
| 角色对话 | `角色名说："台词内容"` | `李明说："你终于来了。"` |
| 多角色对话 | `角色A说："..."，角色B说："..."` | `李明说："你好。"，王芳说："好久不见。"` |
| 内心独白 | `角色名内心独白："..."` 或 `角色名OS："..."` | `李明内心独白："她为什么会在这里？"` |
| 画外音 | `画外音："..."` 或 `旁白："..."` | `画外音："三年后，一切都变了。"` |
| 呐喊/嘶吼 | `角色名大喊："..."` | `李明大喊："不——！"` |
| 低语/耳语 | `角色名低声说："..."` | `李明低声说："别出声。"` |

### 2.3 写台词的注意事项

- **台词必须完整写入**：不能只写"角色A说话"或"角色A与角色B对话"，必须写出具体台词内容
- **标注说话角色**：每句台词前必须标注是谁在说，避免模型混淆
- **台词用双引号**：台词内容用中文双引号`""`包裹，与提示词其他内容区分
- **情绪标注**：可以在角色名后标注情绪（如`李明愤怒地说："..."`），帮助模型生成对应语气的语音
- **长台词拆分**：单镜台词不宜过长（建议不超过30字），长台词应在分镜阶段拆分到多镜
- **内心独白/画外音也要写**：不能只写现场对话，内心独白和画外音同样要写进提示词
- **不要用TTS补救**：如果生成的视频没有语音或语音不清，检查提示词中台词是否写清楚，调整后重新生成，而不是用TTS单独合成

### 2.4 提示词中台词的位置

台词应写在提示词的**画面描述之后**，作为画面内容的一部分。示例：

```
中景，李明站在窗前，背影对着镜头，窗外是雨夜。
李明说："你终于来了。"
王芳从门口走进来，说："我知道你会等我。"
```

不要把台词单独列在提示词末尾或开头，要融入画面描述中，让模型理解台词与画面动作的对应关系。

### 2.5 生成后检查语音

视频生成后，预览时必须检查：
- 有台词的镜头是否有角色语音，且场景有真实环境音（而非只有配乐、无人声）
- 语音内容是否与提示词中写的台词一致
- 语音是否清晰可辨
- 多角色对话时，不同角色的声音是否有区分

如果语音缺失或不清：
1. 检查提示词中台词是否完整写出、是否标注了说话角色
2. 调整台词写法（更明确地标注角色和情绪）后重新生成
3. 不要用TTS单独合成语音来补救

## 三、生成时先展示完整提示词 ＋ 成片后随片交付 ＋ 强制图片参考

### 3.1 提示词生成时先展示、成片后随片透明交付

**每次生成视频先完整展示详细提示词、展示提示词的同时直接生成（不停下等待确认）；成片后用代码块把完整详细的提示词连同成片、完整脚本/分镜一起给用户看**，提示词必须完整、透明，不得省略或事后补。

**展示格式**：
```
【生成后交付 — 镜头XX】
[内嵌预览播放器：该镜头成片]
模型：seedance_2.5
模式：图生视频（带参考图）
时长：XX秒
比例：XX:XX
参考图：@图片1（角色A）、@图片2（角色B）
完整脚本/分镜：[该镜头脚本/分镜]

完整提示词：
```
[此处粘贴完整提示词，包含画面描述/人物@艾特/台词/运镜/光影]
```

用户看完成片、觉得合适，才生成下一个；不合适则按意见改提示词/重生成该视频再审。
```

**展示要求**：
- 提示词必须完整，不能省略、不能只给摘要、不能事后补
- 用代码块包裹，方便用户复制
- 明确标注模型、模式、时长、比例、参考图，并与成片、完整脚本/分镜一起交付
- 每个视频生成后随成片一起给用户看；**用户认可这个成片后才生成下一个**，不未经认可连续批量自动出全部片段
- 用户在生成后提出修改时，按意见调整提示词/重生成该视频，再随成片重新展示完整提示词

### 3.2 强制图生视频，禁止纯文字生成

**每次生成必须使用图生视频模式（带参考图），绝对不允许纯文字生成（文生视频）。**

- 用户提供的人物图片必须作为参考图传入视频生成工具
- 提示词中必须用`@图片N`格式艾特对应的人物
- 即使是场景空镜/过渡镜，也应使用场景参考图或前一镜末帧作为参考
- 禁止以"没有合适参考图"为由使用纯文字生成——没有参考图时用前一镜末帧或场景图

### 3.3 人物图片一人一角色，不得重复

- 用户提供的每个人物图片只对应剧中一个角色
- 同一张参考图不得用于两个不同角色
- 多余角色（无参考图的）只用纯文字描述外貌，不@任何图片
- 生成前建立角色-参考图对应表，全剧保持一致
- 详细规则见 [03-prompt-generation.md](03-prompt-generation.md) 第3.2节

## 四、生成任务卡

### 4.1 每镜建立任务卡

生成前，为每个镜头建立独立的任务卡，记录所有生成参数和状态。

```
【镜头任务卡】
镜号：01
所属场景：场景A
分镜组：分组1
优先级：P0/P1/P2
生成引擎：seedance_2.5（默认）/ 即梦 / MiniMax
Prompt：[完整提示词，原文透传，有台词必须写进提示词]
是否有台词：是/否（有台词时提示词中必须包含角色台词）
参考图：@图片1（角色锚定）、@图片2（场景参考）
生成模式：文生视频/图生视频
画幅：9:16/16:9/21:9/4:3/1:1/3:4
时长：X秒（5-30整数）
依赖：无/依赖镜XX的末帧
状态：待生成/生成中/已完成/已交付预览/需重试/已废弃
版本：v1/v2/v3
预览播放器：[内嵌预览播放器交付状态]
生成结果链接：[公共访问链接]
自检结果：已展示/需修改（成片+脚本+提示词一起交付用户看，用户认可才生成下一个，不未经认可连续批量出片，用户可随时插话）
问题记录：[如有问题，记录问题类型和严重度]
```

> 字段说明：`依赖` 除"镜XX的末帧"外，跨组时可填"依赖 G0X 技术全景锚点帧（33号，见 references/33-tech-panorama-anchor.md）"。

### 4.2 优先级分级

| 优先级 | 定义 | 处理顺序 |
|---|---|---|
| P0 | 反转镜、高潮镜、结尾悬念镜、开场钩子镜 | 最先生成，优先重试，最多3次 |
| P1 | 核心冲突推进镜、关键对白镜、情绪爆发镜 | 第二批生成，最多2次 |
| P2 | 过渡镜、空镜、反应镜、环境镜 | 最后生成，1次即可，不合格可后期修复 |

**原则**：P0镜头质量直接决定全片成败，必须投入最多资源；P2镜头可以接受瑕疵，用后期弥补。

## 五、批次策略

### 5.1 按场景分组

- 同一场景的镜头放在同一批次生成
- 单批≤6个镜头（避免批量生成时质量下降）
- 超过6镜的场景拆分为多批
- 不同场景的镜头不要混在一批（场景风格差异会影响生成质量）

### 5.2 批次内顺序

同一批次内，按以下顺序生成：
1. 先生成P0镜头（反转/高潮/悬念）
2. 再生成P1镜头（核心冲突/关键对白）
3. 最后生成P2镜头（过渡/空镜/反应）

### 5.3 批次间衔接

- 视频逐个生成、逐个审核：每个视频把成片+脚本+提示词给用户看，**用户认可这个成片后，才生成下一个**；不未经认可连续批量自动出全部片段
- 连续镜头（镜A→镜B）：镜B的首帧参考镜A的末帧
- 如果镜A质量不合格或用户不认可，先按意见修复/重生成镜A并再获认可后，再生成镜B（避免错误传递）

## 六、连续镜首帧处理

> ⛔ **铁律30 对齐说明**：本节是**连续镜链式衔接**——复用镜A**已经生成出来的视频**的末帧作为镜B的参考，属于「复用既有视频帧保连贯」，**不是**逐镜新做「关键帧/定帧图成品」。不设「先出关键帧再图生视频」环节；视频模型要挂参考图时，优先用已审核资产图（角色 @图片N / 场景空镜 / 机位底图）或本节的前一镜末帧，不专门新出静态关键帧图。

### 6.1 首帧参考策略

对于连续的两个镜头（镜A→镜B），为了保证视觉连贯性：

- **镜B的首帧**：使用镜A的末帧作为参考图（图生视频模式）
- **镜B的Prompt**：在Prompt中描述"从[镜A末帧状态]开始，[镜B的动作]"
- **光线/场景**：镜B的光线和场景描述必须与镜A一致

### 6.2 首帧参考的适用场景

| 场景 | 是否用首帧参考 | 原因 |
|---|---|---|
| 同场景连续动作 | ✅ 是 | 保证动作连贯、空间连续 |
| 同场景对话正反打 | ✅ 是 | 保证光线、空间一致 |
| 同场景但时间跳转（如"一小时后"） | ⚠️ 可选 | 光线可能变化，可调整 |
| 不同场景切换 | ❌ 否 | 场景不同，不需要连续 |
| 蒙太奇快切 | ❌ 否 | 刻意不连续，制造节奏 |

### 6.3 首帧参考操作

1. 生成镜A，获取镜A的视频文件
2. 截取镜A的最后一帧（末帧）作为图片
3. 上传末帧图片，获取公共访问链接
4. 生成镜B时，使用图生视频模式，首帧参考图=镜A末帧
5. 在Prompt中描述从末帧状态开始的动作

> ⛔ 组间（分镜组与分镜组之间）的整组状态锚点另见 references/33-tech-panorama-anchor.md《技术全景链式锚定法》：本节管“组内镜间”的动作连贯（复用剧情镜头自然末帧）；33 管“组间”的整空间动态状态快照。模式A在组尾追加1秒无对白技术全景、拼前剔除；模式B在正片完成后另生成5秒技术补段、不进filelist。二者互补叠加，不要把33的锚点帧误当本节的镜末帧。

## 六+、段间衔接片段生成（⛔ 铁律31：段间必做衔接）

分镜中标注「需衔接片段」处，**在生成下一段之前，先把衔接片段作为独立镜头生成**；标注「硬切连贯」处直接连续生成、不加片。

**生成顺序与调度**：
1. 生成上段（如 G03）→ 2. **生成衔接片段（G03a / G03-G04衔接）** → 3. 生成下段（G04）。
- 衔接片段与普通镜头同等要求：**图生视频、@ 已审核资产 / 机位底图**，提示词写法见 03 号 §3.10。
- **连贯铁律：上段动作 / 动线 / 朝向终点＝衔接起点，衔接终点＝下段起点**；遵守脸 / 服装 / 站位一致、不越轴、不出关键帧。
- 衔接类型：①动作延续 ②跨场转场（可含环境空镜）③情绪 / 反应缓冲 ④视线引导 ⑤道具特写 ⑥同场景不同时间。
- 时长通常 2–5 秒（长转场可更长）；可纳入相邻 30 秒组，或单独生成。
- 衔接片段同样**生成后随成片 + 完整提示词给用户看、认可才继续**，逐个审核，不未经认可批量出片。
- 衔接片段交付编码与普通片段一致：H.264(yuv420p)+AAC、faststart、**不压缩画质**；源已兼容则流拷贝。

> 注意区分：本节“衔接片段”是要进正片的过渡镜头；33号技术素材（见 references/33-tech-panorama-anchor.md）不进正片——模式A拼前剔除，模式B不进filelist。二者都在组间加片但用途相反，勿混用。

## 七、重试与版本管理

### 7.1 重试触发条件

生成完成后，立即审核（见模块5质量审核）。以下情况需要重试：
- 面部崩坏（换脸/五官扭曲/多余手指）
- 场景跑偏（与Prompt描述的场景不符）
- 动作完全错误（与Prompt描述的动作不符）
- 光影异常（无来源光/过曝/全黑）
- 合规问题（出现血液/暴力/违规内容）
- 时长严重不符（生成时长与目标差>20%）

以下情况不需要重试（可后期修复）：
- 轻微动作卡顿
- 光影小差异
- 背景细节模糊
- 轻微色彩偏差

### 7.2 重试次数上限

| 优先级 | 最大重试次数 | 超过后处理 |
|---|---|---|
| P0 | 3次 | 导演决策（重新设计镜头/用替代镜头） |
| P1 | 2次 | 导演决策（调整Prompt/换景别/用替代镜头） |
| P2 | 1次 | 接受当前版本，后期修复 |

**铁律**：同一镜头重试不超过3次。3次仍不合格，停止重试，进入导演决策流程（见模块7），不要无限重试浪费资源。

### 7.3 重试时的Prompt调整

每次重试，必须调整Prompt，不能用完全相同的Prompt重新生成：

- **第1次重试**：微调Prompt（增加细节描述/调整光线/明确动作）
- **第2次重试**：较大调整（换景别/换机位角度/简化动作/增加参考图）
- **第3次重试**：根本性调整（拆分镜头/用替代镜头/改变调度，见模块7导演决策）

### 7.4 文件 / 版本命名与管理

- 所有保存文件（视频片段 / 成片 / 资产图 / 分镜 / 封面）**按内容命名、长度 4–20 字、见名知意、不重名，并带镜头 / 段落编号**；禁止 `未命名 / 新建文档 / tmp / 视频1` 等空泛名。
- 命名格式：`镜号_内容描述[_版本].mp4`（如 `01_女主推开木门_v1.mp4`、`G03_农奴主鞭打农民_近景.mp4`）
- 每个镜头的每个版本独立保存、不覆盖；版本在内容名后追加 `_v1 / _v2`，终选版本标记 `_final`，但**不得用版本号替代内容名**
- 每个版本都必须上传并提供公共访问链接
- 保留所有历史版本，便于对比和回退
- **交付编码**：片段 / 成片统一 H.264(yuv420p)+AAC、faststart；源已是该格式（Seedance 通常直接输出）一律 `-c copy` 流拷贝、零重编码零画质损失，仅 HEVC/非 yuv420p 才视觉无损转码（CRF16–18，不缩放、不降帧）。详见 06 / 07 号与铁律25。

**版本记录表**：
```
镜号 | 版本 | 生成时间 | Prompt版本 | 问题记录 | 状态
01   | v1   | 09-07 14:00 | Prompt v1 | 面部微崩坏 | 废弃
01   | v2   | 09-07 14:05 | Prompt v2 | 动作略卡 | 备选
01   | v3   | 09-07 14:10 | Prompt v3 | 合格 | 终选(final)
```

### 7.5 废片留存（🗑️ 不删除、统一归档）

- 生成过程中**所有废片——穿模 / 意外字幕或文字 / 脸崩 / 服装错位 / 走位错 / 越轴 / 音画不同步 / 用户否决 / 生成失败——一律不删除，全部保留在项目内**。
- **统一归档并标注**：
  - 视频废片 → `04_视频/废片/`；资产废图 → `02_资产/废片/`；
  - 文件名保留原编号并加「废片」前缀，例：`废片_G03_农奴主鞭打_手部穿模.mp4`。
- 在《资产审核确认表》或新增的《废片清单》登记：**文件名、日期、废片原因**。
- **仅合格、经用户确认的片段进入 `05_成片`**；废片只留存备查，**不参与硬拼接、不对外交付**。
- 与门控衔接：**被用户否决的片段即归为废片保留，不覆盖、不删除原生成结果**。

## 九、内嵌预览播放器交付 + 公共访问链接（全局铁律）

### 9.1 铁律内容

**每生成完一个视频（包括单镜片段、九宫格成图、最终成片），必须以内嵌预览播放器形式展示在聊天对话中**，用户可直接点击播放按钮预览播放（类似视频消息卡片，内嵌在聊天界面里，无需跳转外部页面）。同时附公共访问链接作为补充。

**两条交付要求缺一不可**：
1. ✅ 内嵌预览播放器（首选，用户直接在聊天里点播放）
2. ✅ 公共访问链接（补充，用户可下载/分享）

### 9.2 执行流程

```
视频生成完成
    │
    ▼
获取视频文件（本地路径或平台返回的临时链接）
    │
    ▼
上传至可公共访问的文件存储（FileBatchUpload工具）
    │
    ▼
获取公共访问URL
    │
    ▼
以内嵌预览播放器形式展示视频（用户可直接在聊天中点击播放）
    │
    ▼
同时附公共访问链接（文字链接形式），并把完整脚本/分镜+完整提示词一起给用户看
    │
    ▼
逐镜自检（意外文字/穿模畸形/脸/服装/站位/180°轴线/音画同步）并展示结果
    │
    ▼
⛔ 等用户认可这个成片后，才生成下一个（不未经认可连续批量自动出全部片段）
    │
    ▼
将链接记录到版本记录表和生成进度表
```

### 9.3 交付格式

**单镜生成完成时**：
```

```

**批次完成时**：


### 9.4 逐个生成、成片必看协议

- **先完整展示提示词、展示提示词的同时直接生成（不停下等待确认）**：生成时先把完整提示词展示给用户，展示后不停下等待确认
- **每个视频生成后必看**：把「成片（内嵌预览）+ 该视频完整脚本/分镜 + 完整提示词（@已审核资产）」一起给用户看，并展示逐镜自检结果
- **用户认可才下一个**：用户觉得合适，才生成下一个；**禁止未经用户认可连续批量自动生成全部/后续片段**
- 用户觉得不合适：按其意见改提示词/重生成该视频，再审通过才往下
- 用户可随时插话提出修改意见；用户要求跳过某条时，记录原因后经用户确认再继续下一条
- **模块之间（剧本→分镜→提示词→视频生成→后期）需用户确认后才推进**：每完成一个模块先自检展示，用户说"可以"再进入下一模块

### 9.5 禁止事项

- ❌ 只说"已生成"不给预览播放器
- ❌ 只给公共链接，不给内嵌预览播放器
- ❌ 只给本地文件路径
- ❌ 生成后忘记以内嵌预览交付就继续下一条
- ❌ 链接失效或无法访问
- ❌ 成片和片段只给一个链接（每个版本都要给预览+链接）
- ❌ 生成后忘记上传，过了临时链接有效期才发现

## 十、即梦平台批量操作指南

### 10.1 图生视频参数设置

- 首帧图：上传**已审核角色锚定图 / 机位底图**，或连续镜时上传前一镜已生成视频的末帧（铁律30：不另出新做的关键帧/定帧图）
- 提示词：粘贴模块3生成的Prompt
- 时长：按分镜标注的时长（5秒/10秒/15秒）
- 画幅：9:16（竖屏）或16:9（横屏）
- 运动强度：文戏=低/中，武戏=中/高
- 参考图权重：角色一致性要求高时调高（0.7-0.8），动作自由度要求高时调低（0.4-0.5）

### 10.2 文生视频参数设置

- 提示词：粘贴模块3生成的Prompt
- 时长：按分镜标注
- 画幅：9:16或16:9
- 运动强度：按场景类型
- 负面提示词：粘贴模块3生成的负向提示

### 10.3 批量生成管理

- 不要一次性提交超过6个生成任务（平台可能限流或质量下降）
- 每批生成完成后，下载所有视频，上传获取公共链接，审核质量
- 合格的标记final，不合格的进入重试流程
- 保持生成任务的有序性，不要混乱提交
