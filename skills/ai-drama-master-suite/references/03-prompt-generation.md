# 提示词生成规范

## 概述

将分镜脚本转化为可直接粘贴到AI视频生成平台的提示词。支持两套生成体系：**MiniMax H3 15秒三流程**（文戏/武戏/九宫格）和**即梦/Seedance三引擎**（横屏电影/竖屏Seedance/通用竖屏）。根据用户使用的平台和需求自动选择。

> 当上游分镜以「分镜组」形式交付时，其标准机器可读输入（`OUTPUT_START/FIELD/END`、场景/角色/物品三行 @图片 映射、配音指令）来自 [22-15s-storyboard-group-template.md](22-15s-storyboard-group-template.md)；本节讲提示词的写作规则。

---

## 一、MiniMax H3 15秒三流程

### 1.1 流程选择决策树

```
用户需求
    │
    ├─ 核心是关系变化/对白/微表情/内心戏 ──→ 文戏模式
    │
    ├─ 核心是高密度打斗/连续攻防/动作奇观 ──→ 武戏模式
    │
    └─ 核心是复杂场景/多角色调度/关键画面需要精确控制 ──→ 九宫格模式
```

**默认选择**：不确定时优先文戏模式（最通用）；动作戏超过50%时选武戏模式；场景复杂或需要精确画面控制时选九宫格模式。

### 1.2 文戏模式

**适用**：关系变化、对白、微表情、内心戏、情绪递进。

**输出结构**：
```
【提示词】
画面规格：16:9，电影质感，真人实拍
时间段：0s-15s

0s-3s：[画面描述]，[动作]，[表情]，[环境]
3s-7s：[画面描述]，[动作]，[表情]，[环境]
7s-11s：[画面描述]，[动作]，[表情]，[环境]
11s-15s：[画面描述]，[动作]，[表情]，[环境]

人物A（@图片1）：[外貌描述，与参考图一致]
人物B（@图片2）：[外貌描述，与参考图一致]

场景：[场景描述，光线，氛围]
```

**文戏写作要点**：
- 每个时间段只描述一个核心动作+一次情绪变化
- 重点写微表情：眼神变化、嘴角微动、呼吸节奏、手部小动作
- 关系变化通过站位距离、视线接触、身体语言体现
- 对白用双引号标注，放在对应时间段
- 环境音和氛围要写（雨声/时钟/空调声等）

### 1.3 武戏模式

**适用**：高密度打斗、连续攻防、动作奇观、追逐、爆发。

**输出结构**：
```
【提示词】
画面规格：16:9，电影质感，真人实拍，60fps
时间段：0s-15s

0s-2s：[起手动作]，[攻击方]出[招式]，[受力方]反应
2s-5s：[连续动作1]，[攻防转换]
5s-8s：[连续动作2]，[重击/特效]
8s-11s：[连续动作3]，[反击/闪避]
11s-15s：[收尾动作]，[结果/情绪]

人物A（@图片1）：[外貌+服装+武器]
人物B（@图片2）：[外貌+服装+武器]

场景：[场景描述，光线，可破坏物]
```

**武戏写作要点**：
- 时间段切分更细（2-3秒一段），确保动作连贯
- 每个动作必须有：攻击方→招式→受力方→反应/结果
- 写清攻防转换（谁在攻、谁在守、何时转换）
- 物理效果要写：击中位置、击退方向、环境破坏、尘土/碎片
- 动作节奏要有变化：快→快→慢（重击）→快→收尾
- 合规替换：不写血液/断肢，用"击退撞墙""鳞甲裂出火星""嘴角溢出液体"代替

### 1.4 九宫格模式

**适用**：复杂场景、多角色调度、关键画面需要精确控制、视觉奇观。

> ⛔ **铁律30（不出关键帧）**：本模式**不**再「先出 3×3 共 9 张关键帧/定帧图、再图生视频」。9 宫格只是**视频提示词内部的时间轴文本网格**——直接在一段视频提示词里按 3×3 时间格描述画面与动作；要挂参考图时**复用已审核资产图（角色 @图片N / 场景空镜 / 机位底图）或前一镜已生成末帧**，不专门新做逐镜关键帧成品。

**单段视频提示词（直接用已审核资产 + 时间轴文本网格生成）**：
```
【视频提示词】
画面规格：16:9，电影质感，真人实拍
时间段：0s-15s

（直接挂已审核资产，不另出关键帧图）
人物A（@图片1）：[外貌描述，与已审核角色锚定图一致]
人物B（@图片2）：[外貌描述]
场景（@图片3 机位底图/场景空镜）：[场景描述，与已审核资产一致]

按时间顺序生成连续视频（3×3 为文本节奏格，非新出图）：
0s-5s：[起手画面/动作] → [过渡] → [小高点]
5s-10s：[发展画面/动作] → [过渡] → [转折]
10s-15s：[收尾画面/动作] → [过渡] → [定格情绪]
```

**九宫格模式要点**（铁律30 口径）：
- 9 个时间格只是**一段 15 秒视频提示词内的文本节奏划分**，不再生成 9 张独立关键帧图
- 人物/场景/机位一致性靠 **@已审核资产图**（角色锚定图、场景空镜、机位底图）锁定，不靠新出关键帧
- 若视频模型必须挂参考图，**复用已审核资产图或机位底图**；连续镜之间才用前一镜已生成末帧做链式衔接（同样不算新做关键帧）
- 适合需要精确控制画面节奏与构图的复杂场景；用户明确点名要某张关键帧/定帧图时才按需单独产出

## 二、即梦/Seedance三引擎

### 2.1 引擎选择

| 引擎 | 画幅 | 质感 | 适用题材 |
|---|---|---|---|
| 横屏电影质感 | 16:9/21:9 | 阿莱65，8K，cinematic | 电影感短剧、品牌片、横屏传播 |
| 竖屏Seedance末世水世界 | 9:16 | 真人实拍，4K/8K，60fps | 末世/水世界/赛博朋克/深海 |
| 通用竖屏 | 9:16 | 真人实拍，4K，30/60fps | 都市/古风/甜宠/悬疑/复仇等所有题材 |

**默认选择**：末世/水世界/赛博朋克题材→竖屏Seedance；其他竖屏需求→通用竖屏；横屏需求→横屏电影质感。

### 2.2 横屏电影质感引擎输出格式

每镜包含：画面描述、即梦Prompt（中英文）、负面提示词。（真实环境音写进提示词并保留——雨声/脚步/风声等；不设配乐 BGM/转场字段，片段之间只硬切。）使用结构化纯文本块，严禁表格。

```
【镜头01】
【画面描述】景别+主体+动作+环境+光影+镜头+情绪
【即梦Prompt（中文）】[中文提示词]
【即梦Prompt（English）】[English prompt]
【负面提示词】[negative prompt]
```

**横屏Prompt写作要点**：
- 前置参数：8K, ARRI Alexa 65, cinematic, 16:9, 24fps
- 主体描述：人物外貌（与锚定图一致）+ 服装 + 动作
- 环境描述：场景 + 光线来源 + 色调 + 氛围
- 镜头描述：景别 + 焦段 + 运镜 + 速度
- 情绪描述：通过光影/色调/动作体现，不直接写"sad"
- 画质后缀：detailed skin texture, cinematic lighting, shallow depth of field等

### 2.3 竖屏引擎输出格式（Seedance/通用竖屏）

每5-6镜为一组，每组开头重给场景与人物空间坐标。

```
【分组1：场景名】（镜头01-06）
场景空间坐标：[场景描述+人物站位+前后层次]
人物A（@图片1）：[外貌+服装+异化特征]
人物B（@图片2）：[外貌+服装+异化特征]

【镜头01】
参考图：@图片1（挂已审核角色锚定图锁五官，铁律30：不另出新首帧图）
景别：[景别]
运镜与光影：[运镜方式+速度]+[光源+方向+色调]
画面内容：4K, 8K, 60fps, cinematic lighting, 9:16, [焦段], [主体+动作+环境+神态]
画面台词："[台词]"
强制指令：无字幕
负向提示：[negative prompt]

【镜头02】...
```

**竖屏Prompt写作要点**：
- 前置参数必须包含：4K/8K, 60fps, cinematic lighting, 9:16, 焦段
- 单镜仅一个核心动作（一个动作+一次情绪变化）
- 单镜台词不超过5-7词（长台词拆分多镜）
- 每镜标注人物站位（相对位置/前后层次/朝向）
- 重要道具处于中心安全区
- 主角镜头标注参考图（挂已审核角色锚定图锁五官，铁律30：不另出新首帧图）
- 每镜带强制去字幕指令和负向提示

## 三、通用提示词写作规则

### 3.1 强制图片参考 + @艾特人物（核心铁律）

**每次生成视频必须使用图片参考（图生视频模式），不允许纯文字生成。** 用户提供的人物图片必须在提示词中用@格式艾特出来。

**@艾特格式**：
- 格式：`角色名（@图片N）`，紧跟在角色名后面
- 示例：`李明（@图片1）站在窗前，说："你来了。"`
- 图片引用必须以内联形式出现，不要单独列在末尾
- 每个有参考图的角色都必须标注，不允许遗漏
- 参考图编号与用户提供的图片顺序一致（用户上传的第1张=@图片1，第2张=@图片2，以此类推）

**强制规则**：
- ❌ 禁止纯文字生成（文生视频），必须带参考图
- ❌ 禁止提示词中出现用户提供的角色但不@艾特对应图片
- ❌ 禁止把@艾特放在提示词末尾，必须紧跟角色名
- ✅ 用户提供的每个人物，在提示词中第一次出现时必须@艾特
- ✅ 同一场景中多次出现同一角色，第一次@艾特即可，后续可省略

### 3.2 人物图片一人一角色，不得重复使用

**用户提供的每个人物图片只对应剧中一个角色，绝对不得复用同一张图片扮演多个角色。**

**角色与参考图对应规则**：
- 用户提供N张人物图片 → 锁定N个角色的形象，每张图只对应一个角色
- 剧中角色数量 > 用户提供图片数量时，多余的角色**只用纯文字描述外貌**，不使用任何参考图
- 剧中角色数量 ≤ 用户提供图片数量时，只使用需要的图片，多余的图片不用

**纯文字描述多余角色的格式**：
```
配角王经理：中年男性，约45岁，短发微胖，戴黑框眼镜，穿深灰色西装，表情严肃
```
- 纯文字描述要具体：年龄、性别、发型、体型、服装、标志性特征
- 纯文字描述的角色**不要**@任何图片
- 纯文字描述的角色与有参考图的角色在外貌上要有明显区分，避免观众混淆

**禁止事项**：
- ❌ 用同一张参考图扮演两个不同角色（会导致"一人分饰两角"）
- ❌ 把用户提供的角色A的图片用于描述角色B
- ❌ 为了"省事"给多余角色也套用用户提供的参考图
- ❌ 角色与参考图的对应关系中途更换

**角色-参考图对应表**（生成前必须建立）：
```
角色名 | 参考图 | 描述方式
李明   | @图片1 | 图片参考
王芳   | @图片2 | 图片参考
赵强   | @图片3 | 图片参考
孙丽   | 无     | 纯文字描述：年轻女性，25岁，长发，穿红色连衣裙
周总   | 无     | 纯文字描述：老年男性，60岁，白发，拄拐杖
```

### 3.3 全正向描述结构

- 只陈述"生成什么"，不写"不要什么"
- 负面内容统一放在"负向提示词"部分
- 不使用"no XXX""without XXX""don't XXX"等否定表述
- 用正向描述替代否定：不说"不要模糊"，说"sharp focus, high detail"

### 3.4 双引号规则

- 双引号`""`只用于角色实际台词
- 其他描述不使用双引号
- 台词必须与剧本一致，不擅自修改

### 3.5 台词必须写入提示词（核心规则）

**所有角色对话、内心独白、画外音、旁白，必须直接写进视频生成提示词中**，让AI视频模型直接生成带语音的视频。不使用TTS单独合成语音。

**写台词的格式**：
- 角色对话：`角色名说："台词内容"`（如`李明说："你终于来了。"`）
- 多角色对话：`角色A说："..."，角色B说："..."`
- 内心独白：`角色名内心独白："..."` 或 `角色名OS："..."`
- 画外音：`画外音："..."` 或 `旁白："..."`
- 带情绪：`角色名愤怒地说："..."`、`角色名低声说："..."`

**注意事项**：
- 台词必须完整写出具体内容，不能只写"角色A说话"或"两人对话"
- 每句台词前必须标注说话角色
- 台词写在画面描述之后，融入画面内容中
- 内心独白和画外音也要写进提示词，不能省略
- 长台词（超过30字）应在分镜阶段拆分到多镜
- 如果生成的视频没有语音，检查提示词中台词是否写清楚，调整后重新生成，不用TTS补救

### 3.6 时间段无缺口

- 所有时间段必须连续无缺口完整覆盖目标时长
- 90秒：0s-90s，每镜时间段首尾相接
- 15秒（H3）：0s-15s
- 不允许出现时间重叠或缺口

### 3.7 提示词可直接使用

- 输出的提示词必须可以直接复制粘贴到AI视频生成平台
- 不包含解释性文字、注释、表格
- 不包含"请根据以上生成"等元指令
- 每个提示词是独立完整的，可以单独使用

### 3.8 站位描述模板

**站位是本剧最高优先级视觉一致性项。每个镜头的提示词中必须写清人物站位，不能只写"两人对话"就完事。**

#### ≥2人同框的站位描述标准句式

**标准句式**：
```
角色A（@图片N）站在画面[左/右/中]侧[前/后]景，面向[左/右/镜头/背对镜头]；
角色B（@图片M）站在画面[右/左/中]侧[后/前]景，面向[左/右/镜头]，两人[面对面/并排朝XX方向]相距[X步]。
```

**正面示例：**
```
李明（@图片1）站在画面左侧前景，面向右；王芳（@图片2）站在画面右侧后景，面向左，两人面对面相距一步。
```

```
赵强（@图片3）坐在画面中央偏左，面朝镜头方向，身体微侧向右；孙丽（纯文字）站在画面右侧，面向左，靠在门框上。
```

**反面示例（不合格）：**
```
❌ 李明和王芳站在一起说话。          ← 三要素全缺
❌ 李明在左边，王芳在右边。          ← 缺前后远近、缺朝向
❌ 两人面对面。                      ← 缺左右位置、缺前后远近
```

#### 单人镜头的站位描述标准句式

```
角色A（@图片N）[站/坐/蹲]在画面[中央/偏左/偏右]，面朝[镜头方向/左/右/背对镜头]，[身体微侧向XX]。
```

**正面示例：**
```
李明（@图片1）坐在画面中央偏左，面朝镜头方向，身体微侧向右，双手放在桌上。
```

#### 对话正反打的站位描述

**过肩镜头（OTS）的站位描述：**
```
王芳（@图片2）的肩膀在画面左侧前景（背对镜头），李明（@图片1）在画面右侧中景，面向左，说话。
```

**铁律：**
- 同一场景连续多镜，**左右站位必须保持一致**，除非剧情设计了换位动作
- 正反打镜头中，两人的朝向必须相反（A面向右，B面向左），不得越轴
- 提示词中站位描述必须与分镜脚本中的站位一致，不得自行更改
- 站位描述紧跟在角色动作之前，不能放在段落末尾

### 3.9 角色造型锁定

**提示词中角色的发型/服装/妆容必须与参考图和角色资产锁定表一致。禁止临时发挥导致造型穿帮。**

#### 核心原则

| 元素 | 可否变化 | 规则 |
|---|---|---|
| 面部特征（五官/脸型/肤色/年龄感） | ❌ 永远不变 | 永远与参考图一致，任何场景不得改变 |
| 发型（发色/长度/卷直） | ⚠️ 可变化但必须提前规划 | 如剧情需要变化，必须在角色资产锁定表中提前写明变化触发条件和新造型 |
| 服装 | ✅ 随场景变化 | 每个场景的服装必须在角色资产锁定表中提前规划，提示词中明确写出 |
| 妆容 | ⚠️ 可随场景微调 | 如医院素颜、正式场合淡妆等，提前规划 |

#### 换装场景的提示词写法

**当剧情需要换装时（如医院病号服），提示词必须这样写：**

```
✅ 正确写法：
王芳（@图片2），面部特征与参考图一致（长卷发、鹅蛋脸、大眼睛），身穿蓝白条纹病号服，头发自然披散在肩上。
```

```
❌ 错误写法：
王芳（@图片2），短发病号服，脸色苍白。
```

**错误原因**：参考图是长卷发，提示词写"短发"会导致AI生成时与参考图矛盾——要么脸像参考图但头发变短（穿帮），要么头发跟着提示词变短发（和参考图不是同一个人）。

**正确逻辑**：面部永远跟参考图走；服装可以换；发型如果参考图是长卷发，即使在医院也必须是长卷发（只是没打理、披散着），除非剧情明确写了"剪发"这个事件，且这个事件在角色资产锁定表中有记录。

#### 角色造型描述清单（每个有参考图的角色在提示词中第一次出现时必须写明）

```
角色A（@图片1）：
- 面部特征：与参考图一致（脸型/五官/肤色/年龄感）
- 发型：[当前场景发型，与角色资产锁定表一致]
- 服装：[当前场景服装，与角色资产锁定表一致]
- 妆容：[当前场景妆容，与角色资产锁定表一致]
```

**铁律：**
- 每个角色的造型必须对照角色资产锁定表（见15-consistency-assets.md），不得随意更改
- 造型变化必须有剧情依据，且提前在资产表中规划
- 禁止出现提示词描述与参考图矛盾的情况（参考图长卷发，提示词写短发）
- 同一场景所有镜头，同一角色的造型描述必须完全一致

### 3.10 衔接片段的提示词写法（⛔ 铁律31：段间必做衔接）

分镜中标注「需衔接片段」处，要像普通镜头一样**单独写一条完整提示词**（同样强制图生视频、@ 已审核资产），写法要点：

- **首尾对齐**：提示词开头写清"从〔上段终点的动作 / 动线 / 朝向〕开始"，结尾落到"〔下段起点〕"——**上段终点＝衔接起点，衔接终点＝下段起点**。
- **按衔接类型组织画面**：
  - ①动作延续：脚步连续 / 过门 / 手部承接特写；
  - ②跨场转场：出门—路上—到达，可用无人环境空镜过渡；
  - ③情绪 / 反应缓冲：冲突 / 反转后角色反应、呼吸、停顿；
  - ④视线引导：沿人物视线方向摇移 / 揭示新对象；
  - ⑤关键道具特写：道具承接前后剧情；
  - ⑥同场景不同时间：用光影 / 色温变化表现时间流逝。
- **复用已审核资产与机位底图**：人物 `@图片N`、场景 `@图片N`，遵守脸 / 服装 / 站位一致、不越轴、**不出关键帧**；无字幕、无 BGM（真实环境音可写明并保留）。
- 时长 2–5 秒（长转场可更长）；编号 `G03a` / `G03-G04衔接`，文件名按内容命名。
- 示例（跨场）：
  ```
  图生视频，参考 @图片7（女主）@图片12（雨巷空镜）。中景跟随女主脚步，女主从木门内推门走出（承接上段），镜头随她步入雨夜窄巷，脚步声与雨声连续，画面落到巷口路灯下（接下段室内灯光前）。无字幕，环境音：雨声、脚步、门轴。约3秒。
  ```
- 标注「硬切连贯」处**不写衔接提示词**，避免冗余。

## 四、提示词生成自检门

- [ ] 是否选择了正确的生成流程/引擎？
- [ ] 时间段是否无缺口完整覆盖？
- [ ] **是否确认使用图生视频模式（带参考图），而非纯文字生成？**
- [ ] **用户提供的人物是否都用@图片N格式艾特了？**
- [ ] **@艾特是否紧跟在角色名后面（内联形式）？**
- [ ] **用户提供的人物图片是否一人一角色，无重复使用？**
- [ ] **多余角色（无参考图的）是否只用纯文字描述，未@任何图片？**
- [ ] **是否建立了角色-参考图对应表？**
- [ ] 图片引用是否以内联形式紧跟对应对象？
- [ ] 是否为全正向描述结构（无否定表述）？
- [ ] 双引号是否只出现在角色实际台词中？
- [ ] 有台词的镜头是否在提示词中写出了完整台词？
- [ ] 提示词是否可直接复制粘贴使用（无表格/无解释）？
- [ ] **【站位三要素】每个≥2人同框的镜头，提示词是否写清了左右位置+前后远近+朝向关系？**
- [ ] **【站位单人】单人镜头是否写明了人物在画面中的位置和朝向？**
- [ ] **【站位一致性】同一场景连续多镜，人物左右站位是否保持一致？正反打是否符合180度轴线？**
- [ ] **【角色造型】提示词中角色的发型/服装/妆容是否与参考图和角色资产锁定表一致？**
- [ ] **【角色造型】换装场景是否写了"参考图面部特征+当前场景服装"，而非与参考图矛盾的描述？**
- [ ] **【角色造型】是否禁止了与参考图矛盾的描述（如参考图长卷发却写短发）？**
- [ ] 横屏引擎：是否包含阿莱65/8K/cinematic等前置参数？
- [ ] 竖屏引擎：是否包含4K/8K/60fps/9:16/焦段等前置参数？
- [ ] 竖屏引擎：单镜是否仅一个核心动作？台词是否≤5-7词？
- [ ] 竖屏引擎：是否每5-6镜分组并给出场景空间坐标？
- [ ] 伤害/死亡画面是否已通过合规替换？
- [ ] **【铁律31·衔接提示词】每个「需衔接片段」是否都单独写了完整提示词（首尾对齐上下段、@已审核资产、不越轴不出关键帧、无字幕无BGM）？「硬切连贯」处未冗余写？**
- [ ] 每个提示词是否独立完整可单独使用？
