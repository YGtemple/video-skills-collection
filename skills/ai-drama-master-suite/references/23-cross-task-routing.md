## 一、六大任务类型总路由

主技能默认承接"任务A 短剧/剧情片"。当用户输入命中其他五类任务信号时，按本表路由到对应外部子技能；跨任务项目自动串联，不需要用户手动切换。需求不明确时只问一个简短问题，不抛多选项菜单。

| # | 任务类型 | 识别信号（关键词） | 走哪条路径 | 调用技能/模块 | 产出 |
|---|---|---|---|---|---|
| **A** | 短剧/剧情片/微电影/动态漫/动画短片 | 短剧、微电影、剧情片、动态漫、动画短片、剧本、分镜、角色设定、90秒、5分钟 | 主技能模块 1→7 全流程 | 本技能（ai-drama-master-suite） | 剧本→分镜→资产→提示词→逐镜视频→审核→无损硬拼接粗成片→交付 |
| **B** | 通用商业视频/广告/UGC/企业宣传 | 产品广告、商品广告、UGC、口播、带货、信息流、企业宣传、品牌片、TVC、宣传片 | 商业六步：需求参数锁定→资料门控→分镜表→生成→后期(用户自理)→交付 | `doubao-creative-video`（规划）+ `seedance-25` / `image_to_video` / `text_to_video` / `media_to_video` / `video_edit`（生成） | 商业成片（内嵌预览＋公共链接） |
| **C** | 已有视频素材处理/后期/剪辑/增强 | 剪辑、拼接、裁剪、调速、滤镜、画质增强、转码、抠像、拆条、字幕识别/擦除 | 工具路由决策树（见下） | `byted-mediakit-editing` / `byted-mediakit-video` / `jianying-editor`（复杂多轨） | 处理后的视频文件 |
| **D** | 在线视频提取/下载/转写/理解 | 下载视频、提取字幕、转写、逐字稿、视频总结、画面分析、B站/抖音/YouTube链接 | 三步：下载→(转写)→抽帧理解 | `doubao-video-extract` | MP4文件 / 逐字稿 / 画面分析结论 |
| **E** | 音频制作/处理（独立素材） | 生成音频、配音、音效、人声分离、音频转码 | 生成＋处理两阶段 | `seed-audio`（T2A/A2A）、`byted-mediakit-audio`、`byted-mediakit-editing`（audio域） | 音频文件 |
| **F** | 图片资产生成/处理 | 角色设定图、三视图、场景图、道具图、封面图、关键帧、海报、生图、抠图、OCR | 资产分批确认流程 | `doubao-creative-design`（主入口）、`seedream-50`（用户指定5.0 Pro）、`script-asset-master`（三资产卡）、`byted-mediakit-image`（已有图处理） | 图片资产（逐张 `present_files` 交付） |

**跨任务融合**：一个完整项目通常跨多类。例如短剧全流程 = F（资产）→ A（创作＋生成）→ 只做硬拼接交付（后期用户自理）。

### 任务C 工具路由决策树

```
用户要处理已有视频
  ├─ 裁剪/拼接/调速/音量/滤镜/运镜/音频淡入淡出/动图截取 → byted-mediakit-editing
  ├─ 画质增强/画质检测/抽帧/字幕识别/字幕擦除/高光拆条/剧情分析/场景分段/抠像/转码/OCR → byted-mediakit-video
  ├─ 复杂多轨剪辑/动效/模板/录屏/影视解说 → jianying-editor
  └─ 只说"处理视频"未说明目标 → 先澄清具体目标
```

> ⚠️ **短剧流程内的"后期"不等于任务C**。短剧模块6 只做无损硬拼接、不剪辑不混音（见 [06](06-post-production.md)）；任务C 是用户拿着**外部已有素材**、明确要求精剪/增强/转码时才走。

### 任务D 意图路由

```
用户给视频链接/本地视频
  ├─ 只下载/保存MP4 → doubao-video-extract（media-mode video）
  ├─ 要字幕/逐字稿/文案/总结 → doubao-video-extract（走飞书妙记链路，禁第三方转写）
  └─ 要画面分析/截图/某物是否出现 → 先下载 → 抽帧取证（禁浏览器搜索代替本地MP4分析）
```

支持平台：快手、B站、AcFun、CCTV、芒果TV、梨视频、搜狐、腾讯、微博、X、Facebook、Instagram、TikTok、Twitch、YouTube、视频直链、本地视频。外网平台先查网络环境，口令式链接不支持解析。

## 三、架构设计要点

跨任务时按四层调度（短剧流程已内化为主技能 8 模块，不再重复展开）：

```
用户输入（自然语言 / 已有素材 / 参考图）
  → 入口路由层：六大任务类型识别 + 起始阶段判断 + 缺失信息澄清（只问一个简短问题）
  → 工作流引擎层：任务A走模块1-7（每模块停止等确认）；B/C/D/E/F走对应工作流
  → 子技能调度层：主技能内部模块 + 外部20+子技能融合串联 / 重叠去重
  → 工具执行层：image_to_video / text_to_video / media_to_video / video_edit / mediakit-cli / image_gen / audio 等
```

**关键设计原则**：

1. **每步停止点**：任务A模块之间需用户确认；模块4视频生成内部**先完整展示提示词、展示提示词的同时直接生成（不停下等待确认）；成片后把成片（内嵌预览）+完整脚本/分镜+完整视频提示词（@已审核资产）一起给用户看，用户认可才生成下一个，禁止未经认可连续批量自动出片**（见主 SKILL.md 铁律1/5/8/29）。
2. **上游产物是下游输入**：剧本→分镜→资产→提示词→生成→审核→硬拼接→交付，不跳步；任何步骤失败可回退上一步调整。
3. **主从技能模式**：每步一个主技能（核心逻辑）＋若干辅助技能（补充能力）。
4. **全局铁律跨技能强制执行**：Seedance 2.5优先、提示词原文透传、每次生成先完整展示提示词、展示同时直接出片（不停下等待确认）、成片后随片交付脚本/提示词、强制图生视频@艾特、一人一角色、内嵌预览交付、台词与环境音写进提示词不用TTS、全片零字幕（黑卡例外）、只硬拼接不剪辑、原画质零压缩、脸不崩＋服装同阶段锁死、美术资产AI可直接生成但出图必审通过才定稿@、成片必查意外字幕/穿模——这些是跨所有子技能的统一约束，详见主 SKILL.md 铁律 0–39，不在此重复。

| 剧本：本技能模块1 / blockbuster-script-director | 按需求选 | 从零原创走模块1；有原作改编走 blockbuster |

### 4.3 串联顺序原则

1. **创作在前，制作在后**：剧本→分镜→资产→提示词→生成→审核→硬拼接→交付
2. **图片在前，视频在后**：先生成角色/场景资产，再图生视频
3. **单镜在前，多镜在后**：先逐镜生成确认，再做跨镜一致性检查
4. **内容在前，形式在后**：先定画面内容；滤镜/调色/字幕属后期，**用户自理**；人为配乐 BGM 不添加（真实环境音随片保留）
5. **生成在前，处理在后**：先用AI生成原始素材，后期处理由用户在剪辑软件完成

## 五、常见决策树

### 5.1 用户说"帮我做个视频"
1. 澄清：什么类型？（短剧 / 广告 / 宣传 / 素材处理 / 下载链接 / 音频 / 生图）
2. 按第一章路由到任务 A–F
3. 从对应工作流第一步开始

### 5.2 用户提供人物图片要生成视频
1. 进入任务A（或B）
2. 建参考图资产表，一人一角色（[15](15-consistency-assets.md)）
3. 提示词必须 @图片N 紧跟角色名
4. 强制图生视频，不用纯文字
5. 台词写进提示词，模型直接发声；不单独 TTS

### 5.3 用户要求剪辑已有视频
- 若属短剧流程内"合成一条" → 模块6，**只做无损硬拼接**（[06](06-post-production.md)），不剪辑不混音
- 若用户拿外部素材明确要精剪/调速/加特效 → 任务C，走 `byted-mediakit-editing` / `jianying-editor`

### 5.4 用户给了视频链接
1. 进入任务D，调 `doubao-video-extract`
2. 判断目标：下载 / 转写 / 画面分析
3. 需二创则串联任务B或C

### 5.5 视频生成后质量不好
1. 模块5 七维审核定位问题（[05](05-quality-consistency.md)）
2. 轻度→调整提示词重生成；中度→调Prompt重生成；重度→回模块3重设计镜头
3. **脸崩/服装跳变属 P0**：回源头重生成，不用后期掩盖（铁律24）

## 六、常见问题（FAQ）

> 短剧流程内的规则（Seedance 2.5优先、提示词原文透传、强制图生视频@艾特、内嵌预览交付、先展示提示词后直接出片/成片必看/用户认可才下一个、去水印红线等）见主 SKILL.md 铁律 0–39，此处只列跨任务 FAQ。

**Q1：已经有剧本了，能跳过前面步骤吗？**
A：能。按用户已有素材从对应模块切入（剧本→模块2分镜；提示词→模块4生成；视频片段→模块5审核）。见主 SKILL.md 入口路由表。

**Q2：为什么必须用图生视频，不能纯文字？**
A：纯文生视频易角色变脸、场景漂移。参考图＋@艾特是一致性最佳实践。一致性资产表见 [15](15-consistency-assets.md)。

**Q3：没有人物参考图怎么办？**
A：两条路：①用 `doubao-creative-design` / `script-asset-master` 先生成角色设定图（模块2.5）；②多余角色纯文字描述外貌，主角建议有参考图。

**Q4：生成的视频没有语音怎么办？**
A：检查提示词是否写清台词（`角色A说："台词内容"`）。台词必须完整写入提示词，由AI视频模型直接生成带语音的视频。**不使用 TTS 单独合成**（铁律7）。台词过长/语速过快时精简后重生成。

**Q5：可以给视频加 BGM/配乐吗？环境音呢？**
A：分两类对待：
- ✅ **真实环境音允许、鼓励写进提示词**——脚步、雨、风、水流、虫鸣、火焰、衣物摩擦、门轴、马蹄、人群嘈杂、远处犬吠等，由AI视频模型直接生成，随片硬拼接原样保留；拼接时注意片段边界处环境音不要突兀断档。
- ❌ **人为配乐 / BGM / 旋律 score 一律禁止**——歌曲、情绪配乐、钢琴弦乐等，技能不生成、不混入，以免干扰用户在自己的剪辑软件里配音乐。
- **台词与环境音都由模型直接生成，不用 TTS**；后期配乐/混音由用户自理。
- 仅当用户明确要**独立音频素材**（任务E，如单独做一段配乐/音效文件）时，才用 `seed-audio` 生成。

**Q6：可以加字幕吗？**
A：**全片绝对零字幕**（台词字幕/旁白字幕/解释字卡/剧名卡/"未完待续"一律禁止）。唯一例外：时空跳转过渡卡（纯黑底＋居中白色时间文字，如"二十年前"），单屏1–2秒即切走。见铁律20。封面标题文字是另一例外（封面按 [13](13-cover-design.md) 设计）。

**Q7：剪辑用 mediakit 还是剪映？**
A：仅任务C（用户拿外部素材明确要处理）时：简单拼接/裁剪/调速/滤镜用 `byted-mediakit-editing`；复杂多轨/动效/模板/录屏用 `jianying-editor`。**短剧模块6 只做无损硬拼接（concat demuxer ＋ `-c copy` 流拷贝），不调用剪辑能力**，后期用户自理。

**Q8：可以去除视频水印吗？**
A：**全技能不包含、不推荐、不指导任何去水印操作**。建议平台官方无水印导出。见铁律2。

**Q9：如何提升画质？**
A：①生成用 Seedance 2.5（画质优于 2.0_fast）；②**交付保持原画质零压缩**，不重编码不降清（铁律25）；③提示词写清光影/皮肤质感描述（术语查 [14](14-cinematic-vocabulary.md)）。不在后期靠 enhance-video 二次增强短剧成片。

**Q10：角色脸崩/服装变了怎么办？**
A：**脸不崩 ＋ 服装同阶段锁死**是 P0 红线。每镜抽帧核对面部与锚定参考图一致；同一剧情阶段服装款式/颜色/配饰锁死，换装必须有剧情/镜头交代（换季、入伍、受伤、身份转变等）。任一不过不交付、不拼入成片。详见铁律24与 [15](15-consistency-assets.md)。

**Q11：一个分镜组/片段做多长？**
A：分镜组时长 **5–30 秒灵活**（不是固定15秒），按故事信息量自然定。格式见 [22](22-15s-storyboard-group-template.md)。

**Q12：要复刻/改编一个已有视频怎么办？**
A：**必启动 `script-asset-master` 重做场景/角色/道具三资产**，再 @图片 图生视频；不要直接拿原片音频硬拼（会嘴型错位）。踩坑经验（删广告段补铺垫、同角色不同年龄段同一张脸、ffmpeg拼接）见 [18](18-lessons-learned-remake.md)、[19](19-success-case-ayong.md)。

**Q13：支持哪些平台下载？**
A：快手、B站、AcFun、CCTV、芒果TV、梨视频、搜狐、腾讯、微博、X、Facebook、Instagram、TikTok、Twitch、YouTube、直链、本地视频。见任务D。

**Q14：生成的视频版权归谁？**
A：AI生成内容版权因地区而异，查看豆包平台用户协议与相关法规。本技能仅提供创作工具，不承担版权责任。

## 七、完整工作流示例：90秒都市悬疑短剧

> 示例只展示跨任务路由与模块衔接；短剧 1→7 各模块的详细规则见主 SKILL.md 与 01–07 号。**后期段已按主技能最新规则改写为"只硬拼接、不剪辑/不调色/不加片头片尾；不加人为配乐 BGM，真实环境音与台词原样保留"。**

**项目**：都市悬疑《代码裂痕》，女主程序员发现自己的代码被篡改（用户指定 9:16 竖屏；未指定画幅时默认横屏16:9，见铁律22）。

| 阶段 | 调用 | 关键动作 | 产出 |
|---|---|---|---|
| ①需求澄清 | `doubao-creative-drama`（规划） | 确认90秒/9:16/钩子驱动；判断从剧本开始 | 规划报告 |
| ②剧本 | 本技能模块1 | 四幕卡点，开场3秒强冲击，结尾悬念；可叠 [09](09-hkkk-formula.md)/[10](10-emotion-design.md) | 完整剧本 |
| ③分镜 | 模块2 ＋ [14](14-cinematic-vocabulary.md) ＋ [22](22-15s-storyboard-group-template.md) | 6个分镜组（5–30秒灵活），双输出格式 | 分镜脚本 |
| ④资产 | `script-asset-master` ＋ `doubao-creative-design` | 主角林晚→配角陈默→场景全景，分批 `present_files` 确认；建 [15](15-consistency-assets.md) 资产表（面部锚定＋服装锁定＋换装节点） | 参考图资产表 |
| ⑤提示词 | 模块3 ＋ `image-reference` | 每镜含 @图片N、站位三要素、台词写进提示词（"林晚说：'这不是我写的代码……'"）、真实环境音写入提示词（办公室空调/机房风扇）、无配乐 BGM、无字幕指令 | 完整提示词（代码块展示） |
| ⑥生成 | 模块4 ＋ `seedance-25` | model_version=seedance_2.5，原文透传，强制图生视频；逐镜内嵌预览→自检（脸/服装/站位）→自动连下一镜 | 6段视频 |
| ⑦审核 | 模块5 ＋ `byted-mediakit-video` | 七维审核＋四维一致性；镜头05场景跑偏→调Prompt重生成 | 审核通过素材 |
| ⑧硬拼接 | 模块6 ＋ [06](06-post-production.md) | **只硬拼接**：ffprobe核对6段规格一致后，concat demuxer ＋ `-c copy` 流拷贝；不裁不入出点、不加转场/人为配乐 BGM/字幕/调色/片头片尾；真实环境音与台词原样保留、注意片段边界音轨衔接；拼后校验音画同步、总时长＝90秒±2秒、原画质零压缩 | 无损粗成片 |
| ⑨交付 | 模块7 ＋ [13](13-cover-design.md) | 内嵌预览播放器＋公共链接；电影海报级封面（9:16，片名式大字）；多平台规格 | 最终成片＋封面 |

**耗时参考**：短剧全流程约3–5小时（时间估算详见 [16](16-project-playbook.md)）；商业15秒单条约30–60分钟；素材处理单操作5–15分钟；在线下载＋转写10–30分钟；独立音频单段2–5分钟；图片单张1–3分钟。
