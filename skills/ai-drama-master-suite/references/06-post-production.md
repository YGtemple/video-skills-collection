# 后期硬拼接交付规范

## 定位（先读这段）

**本技能不替用户做剪辑、不添加人为配乐 BGM、不调色、不做任何后期包装。** 模块6 只做一件事：

> 把用户已经逐镜确认通过的视频片段，按分镜顺序**原样、无损、一刀不裁**地硬拼接成一条粗成片，方便用户下载后导入自己的剪映/Pr/DaVinci 等后期软件继续剪。

**明确不做的事**（用户自理，本技能不代劳）：
- ❌ 不做主动剪辑：不裁入点出点、不调速、不混剪、不蒙太奇、不做节奏重编
- ❌ 不添加人为配乐/BGM/旋律 score、不做四层混音、不后期加音效
- ✅ 保留并原样拼接：台词语音 + 真实环境音（脚步/雨/风/水流/虫鸣/火焰/衣物摩擦/门轴/马蹄/人群嘈杂/远处犬吠等，由视频模型在生成时直接产出）
- ❌ 不调色、不加 LUT、不加暗角、不加锐化/降噪
- ❌ 不加片头片尾卡、不加字幕、不加转场特效、不加水印
- ❌ 不做任何"让成片更好看"的二次加工

**交付物性质**：给用户的是"**硬拼接粗成片（原样拼接、未做任何处理）**"，不是"已完成的最终成片"。必须明确告诉用户：这条片子可以直接拖进他自己的剪辑软件继续精剪。

---

## 一、核心红线：零改动、零重编码、音画同步

### 1.1 零改动原则

拼接后的粗成片，每一个镜头的画面和声音都必须与单镜原始文件完全一致：
- **一刀不裁**：不修剪任何镜头的入点/出点，开头结尾帧原样保留
- **不重编码**：规格一致时用流拷贝（`-c copy`）拼接，不重新压缩视频/音频
- **不调速**：不做任何快慢速处理，每镜原始时长原样保留
- **不重采样**：不改分辨率、不改帧率、不改采样率、不改声道
- **不添加任何额外声音**：不后期加配乐/BGM/音效；视频模型生成时自带的台词与真实环境音原样保留

### 1.2 音画同步铁律

**严禁出现"嘴没张声音先到""声音滞后于画面""口型对不上"**。

- 单镜内音画同步由 Seedance 2.5 生成时保证（台词写进提示词，视频自带语音）
- 镜头与镜头之间的拼接点，必须保证上一镜音频结束的瞬间，下一镜画面/音频才开始——不允许上一镜的尾巴声音漏到下一镜画面里
- **环境音边界衔接**：拼接保留各段自带的真实环境音，检查镜头边界处环境音是否自然连续（同场景同时间段的雨/风/人群声不应突变或重叠）；不同场景切换时环境音自然切换即可，不做后期桥接
- 拼接完成后必须逐边界抽帧校验（见 §四）

## 二、拼接前：逐段核对规格（ffprobe）

在拼接之前，**必须先用 ffprobe 逐段检查所有终选镜头的规格是否一致**。各段本就来自同一 Seedance 2.5 管线，理应同规格；但仍要逐段确认，避免某段被意外重新导出过。

### 2.1 必须核对的项

| 项目 | 为什么要一致 |
|---|---|
| 视频编码（codec_name） | 不一致时 `-c copy` 会花屏或无法播放 |
| 分辨率（width × height） | 不一致时拼接会拉伸/黑边/错位 |
| 帧率（r_frame_rate） | 不一致时会出现丢帧/重复帧/时长漂移 |
| 像素格式（pix_fmt） | 不一致时可能色彩异常 |
| 音频编码（codec_name） | 不一致时音轨会断裂 |
| 音频采样率（sample_rate） | 不一致时 pitch 异常/时长偏移 |
| 声道数（channels） | 不一致时声像错位 |

### 2.2 核对命令（AI 自行运行，用户不碰终端）

```bash
# 逐段输出规格，人工/脚本比对
for f in shot*.mp4; do
  echo "=== $f ==="
  ffprobe -v error \
    -select_streams v:0 \
    -show_entries stream=codec_name,width,height,r_frame_rate,pix_fmt \
    -of default=noprint_wrappers=1 "$f"
  ffprobe -v error \
    -select_streams a:0 \
    -show_entries stream=codec_name,sample_rate,channels \
    -of default=noprint_wrappers=1 "$f"
  echo -n "duration: "
  ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 "$f"
done
```

### 2.3 规格不一致时的处理（重要）

- **规格一致** → 进入 §三，用 concat demuxer + `-c copy` 流拷贝拼接
- **规格不一致** → **禁止用 `-c copy` 硬拼**（会花屏、音画不同步、时间戳错乱）。先分清是哪类不一致：
  1. **分辨率 / 帧率 / 画幅 / 采样率 / 声道不一致**：
     **首选回到模块4，把不一致的那一段按统一规格重新生成或重新导出，源头对齐后再拼**；**不靠缩放、转帧率、重采样来"对齐"成片**（那必然损失画质）。
  2. **仅编码 / 像素格式不兼容**（如某段是 HEVC/H.265、非 yuv420p，而其余为 H.264）：
     可对该段做**视觉无损的兼容性转码**为 H.264(yuv420p)+AAC，**不缩放、不降帧率、不降噪、不调色、不丢帧**，命令见 §五。
  3. **实在无法重新生成**（如该镜已废弃、用户接受现状）：才做一次性统一处理，且必须保留所有原始单镜文件（不覆盖），明确告知用户"已做一次性处理，画质可能有轻微损失"，并同时提供原始素材包。

## 三、拼接：concat demuxer + 流拷贝（-c copy）

规格全部一致时，用 concat demuxer 直接流拷贝，**不重新编码**，速度秒级，零质量损失。

### 3.1 步骤1：建 filelist.txt

按分镜顺序，每行一个文件（顺序即成片顺序）：

```
file 'shot01.mp4'
file 'shot02.mp4'
file 'shot03.mp4'
...
```

> ⛓️ **段间衔接片段（铁律31）按序插入两段之间**：分镜中标注「需衔接片段」的衔接镜头（如 `G03a_G03-G04衔接.mp4`），在 filelist 中放在它所连接的两段之间：
> ```
> file 'G03_xxx.mp4'
> file 'G03a_G03-G04衔接.mp4'
> file 'G04_xxx.mp4'
> ```
> **衔接片段与普通镜头一样流拷贝、不改动原片段**；标注「硬切连贯」处无衔接文件、两段直接相邻。衔接片段必须已通过用户审核，且其起点接上段终点、终点接下段起点。
>
> 🗑️ **废片不进 filelist**：只有**合格、经用户确认**的片段（含合格衔接片段）才写入列表并进入 `05_成片`；穿模 / 意外文字 / 脸崩 / 服装错位 / 走位错 / 越轴 / 音画不同步 / 用户否决 / 生成失败的废片**一律不删除**，归档到 `04_视频/废片/`（废图到 `02_资产/废片/`）、加「废片」前缀并登记原因，**不参与硬拼接、不对外交付**。
>
> 🧹 **技术全景素材（33 号，见 references/33-tech-panorama-anchor.md）不进 filelist**：模式A中，非末组视频末尾的1秒技术全景从一开始就不属于正片，拼前剔除并归档到 `04_视频/锚点尾/`；模式B中，正片完成后另生成的5秒技术补段不进filelist，同样归档。技术素材仅作下一组锚点帧来源，**不删除、不交付、不进filelist**。若模式A边界没有关键帧、无法精确流拷贝切尾，转模式B，不静默重编码；排除技术素材后，剩余正片仍按“一刀不裁、`-c copy` 流拷贝”硬拼。

### 3.2 步骤2：流拷贝拼接

```bash
ffmpeg -f concat -safe 0 -i filelist.txt -c copy -movflags +faststart rough_cut.mp4
```

参数说明：
- `-f concat`：使用 concat demuxer（按文件列表顺序拼接）
- `-safe 0`：允许相对路径
- `-c copy`：**流拷贝，不重编码**——视频/音频原始数据原样复制，零质量损失、零时间戳偏移风险最小
- `-movflags +faststart`：把 moov 元数据前置（只重排容器、**不触碰码流、不影响画质**），便于 Windows 双击、聊天预览边下边播

> 源片段本就是 H.264(yuv420p)+AAC 时（Seedance 通常直接输出此格式），上面这条流拷贝命令就是最终交付，零重编码、零画质损失。

### 3.3 为什么必须用 -c copy

- 重编码（去掉 `-c copy`，让 ffmpeg 默认重编码）会引入：
  - 二次压缩损失（哪怕 CRF 18 也比原片多一代损失）
  - 时间戳重排，可能导致镜头边界处音画轻微错位
  - 耗时大幅增加
- 流拷贝是"无损串接"，只改容器不改码流，是用户最担心的"嘴型/声音错位"问题的最优解

## 四、拼后强制校验（不通过就重拼，不带病交付）

拼出 `rough_cut.mp4` 后，**必须逐项校验**，任何一项不通过就排查原因重拼，不能直接交付。

### 4.1 总时长校验

```bash
# 各段时长之和
total=0
for f in shot*.mp4; do
  d=$(ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 "$f")
  total=$(echo "$total + $d" | bc -l)
done
echo "expected total: $total"

# 成片实际时长
ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 rough_cut.mp4
```

**合格标准**：成片时长 ≈ 各段时长之和（误差在 0.1 秒内为正常 AAC 编码填充；偏差超过 0.5 秒说明有丢帧/多帧，必须排查）。

> **⚠️ 使用 33 号技术全景锚点法时**（见 references/33-tech-panorama-anchor.md）：成片时长只计**正片片段时长之和**。模式A每组从原始生成时长中排除末尾1秒技术尾；模式B直接排除独立5秒技术补段。总时长校验通过标准不变（±0.1s）；若把技术素材计入，时长必然偏大。

### 4.2 流规格校验

```bash
ffprobe -v error \
  -show_entries stream=codec_name,width,height,r_frame_rate,sample_rate,channels,codec_type \
  -of default=noprint_wrappers=1 rough_cut.mp4
```

**合格标准**：成片的视频流参数、音频流参数与单镜完全一致（流拷贝不应改变任何参数）。

### 4.3 镜头边界音画同步抽帧校验

在每个镜头切换的时间点（即各段时长累计处），抽 3 帧：切换前 1 帧、切换点、切换后 1 帧。

```bash
# 示例：假设 shot01 长 2.0s，shot02 从 2.0s 开始
# 抽 1.9s / 2.0s / 2.1s 三帧
ffmpeg -ss 1.9 -i rough_cut.mp4 -frames:v 1 check_before.jpg
ffmpeg -ss 2.0 -i rough_cut.mp4 -frames:v 1 check_at.jpg
ffmpeg -ss 2.1 -i rough_cut.mp4 -frames:v 1 check_after.jpg
```

**人工/视觉确认**：
- 1.9s 帧是上一镜画面，2.1s 帧是下一镜画面，没有画面残留/闪烁
- 对应时间点的音频波形：用 `ffprobe -show_packets` 听感或波形图确认，上一镜声音结束点和下一镜画面起点对齐，没有"上一镜台词尾巴漏到下一镜画面上"
- 无黑帧、无花屏、无冻结帧

### 4.4 完整性校验

- [ ] 总时长 = 各段时长之和（±0.1s）
- [ ] 视频流编码/分辨率/帧率与单镜一致
- [ ] 音频流编码/采样率/声道与单镜一致
- [ ] 每个镜头边界处画面正确切换、音频无串台
- [ ] 无丢帧、无重复帧、无黑帧、无花屏
- [ ] 随机抽 2-3 处播放，音画同步正常

### 4.5 交付编码必检（⛔ 铁律32，不达标不交付）

```bash
# 1) 确认视频流=h264、音频流=aac
ffprobe -v error -show_entries stream=codec_name,codec_type -of csv=p=0 rough_cut.mp4
# 期望输出包含：
# h264,video
# aac,audio

# 2) 确认像素格式=yuv420p
ffprobe -v error -select_streams v:0 -show_entries stream=pix_fmt -of csv=p=0 rough_cut.mp4
# 期望：yuv420p
```

- [ ] 视频流编码 = **h264**、像素格式 = **yuv420p**；音频流编码 = **aac**
- [ ] 封装含 **faststart（moov 前置）**——拼接命令已带 `-movflags +faststart`；文件可快速起播
- [ ] 源为 H.264+AAC 时全程 **`-c copy` 流拷贝**（无重编码、画质零损失）；仅 HEVC/非 yuv420p 才按 §五 视觉无损转码（CRF16–18，不缩放、不降帧）
- 任一项不达标：不交付，修正封装 / 转码后重新检查。

### 4.6 ★ 单文件 Windows 兼容封装门（⛔ 铁律32 第一道门 · 任何 .mp4 落盘给用户前必过）

> **为什么单独开这一节**：视频模型（Seedance / 即梦 / 可灵等）下载下来的原始 mp4 **不能直接交付**——它可能是 HEVC、yuv420p10、音频 Opus、或没 faststart，Windows 自带播放器/聊天预览就会报「编码不对/打不开」。
> **适用范围（全覆盖，不只是拼接成片）**：每一段单镜视频、衔接片段、人物/场景/道具预览视频、硬拼接粗成片——**任何一个要写进 `D:\豆包产物\短剧项目\...` 给用户双击播放的 .mp4，落盘前都必须先过这道门**。
> **本机已确认**：ffmpeg/ffprobe 在 PATH 上（WinGet Gyan build），PowerShell 直接调用即可。

#### 第一步：探测（PowerShell，照抄）

```powershell
$in = "原始视频.mp4"   # 改成实际文件路径
ffprobe -v error -select_streams v:0 -show_entries stream=codec_name,pix_fmt -of csv=p=0 $in
ffprobe -v error -select_streams a:0 -show_entries stream=codec_name -of csv=p=0 $in
# 期望看到：h264,yuv420p  和  aac
```

#### 第二步：一键封装（自动判断流拷贝 or 视觉无损转码，PowerShell 照抄）

```powershell
$in  = "原始视频.mp4"
$out = "交付_兼容版.mp4"   # 输出到 04_视频\ 或 05_成片\ 下，按内容命名

$vcodec = (ffprobe -v error -select_streams v:0 -show_entries stream=codec_name -of csv=p=0 $in).Trim()
$pixfmt = (ffprobe -v error -select_streams v:0 -show_entries stream=pix_fmt -of csv=p=0 $in).Trim()
$acodec = (ffprobe -v error -select_streams a:0 -show_entries stream=codec_name -of csv=p=0 $in).Trim()

if ($vcodec -eq 'h264' -and $pixfmt -eq 'yuv420p' -and $acodec -eq 'aac') {
    # 已兼容：只重排容器加 faststart，码流原样、零画质损失
    ffmpeg -y -i $in -c copy -movflags +faststart $out
} else {
    # 不兼容（HEVC / yuv420p10 / opus 等）：视觉无损转码，不缩放、不降帧、不降噪、不调色
    ffmpeg -y -i $in -c:v libx264 -crf 17 -preset slow -pix_fmt yuv420p `
          -c:a aac -b:a 256k -ar 48000 -ac 2 `
          -movflags +faststart $out
}
```

#### 第三步：复检（不通过不许交付）

```powershell
ffprobe -v error -show_entries stream=codec_name,codec_type -of csv=p=0 $out
ffprobe -v error -select_streams v:0 -show_entries stream=pix_fmt -of csv=p=0 $out
# 必须见：h264,video  +  aac,audio  +  yuv420p
```

**硬约束**：
- ✅ 已兼容就 `-c copy`，**绝不重编码**（零画质损失）；
- ⚠️ 只有编码/像素格式真不兼容才走转码，且 **CRF 17、无 scale、无 fps、无降噪、无调色**；
- ✅ 始终带 `-movflags +faststart`（moov 前置，Windows 双击即播、不卡开头）；
- ✅ 复检通过后，把 `$out` 作为交付文件；**原始文件保留不删**（归 `04_视频\` 或 `废片\`）。
- ❌ 严禁把模型原始下载文件、未过此门的 mp4 直接复制到 `04_视频\` / `05_成片\` 交给用户。

## 五、兼容性转码：仅编码 / 像素格式不兼容时（视觉无损，不缩放、不降帧）

**触发条件很窄**：仅当某段是 HEVC/H.265、或像素格式非 yuv420p 等**编码层不兼容**，且无法回源头重新导出时使用。**分辨率 / 帧率不一致不走这里**——那类问题回模块4重新生成对齐，不做缩放、不转帧率。

```bash
# ① 仅视频编码不兼容（如 HEVC）；音频若已是 AAC，直接 -c:a copy
ffmpeg -i input_hevc.mov \
  -c:v libx264 -crf 17 -preset slow -pix_fmt yuv420p \
  -c:a copy \
  -movflags +faststart \
  output_h264.mp4

# ② 若音频也不兼容（非 AAC），把 -c:a copy 换成：
#   -c:a aac -b:a 256k -ar 48000 -ac 2
```

**关键约束（画质铁律）**：
- **没有 `-vf scale`、没有 `fps=` 滤镜**——分辨率、帧率、画幅与源完全一致；
- `-crf 17`（可在 16–18 间，越低越接近无损）或直接沿用源码率；`-pix_fmt yuv420p` 只统一像素格式；
- **不降噪、不调色、不丢帧**，只做编码 / 封装兼容；
- 逐段转码兼容后，再回 §三 与其余 H.264 片段一起 `-c copy` 流拷贝拼接。

**使用此命令时必须**：
1. 保留所有原始单镜文件（不删除、不覆盖）
2. 向用户明确说明："由于某段编码不兼容（如 HEVC），已做一次视觉无损转码为 H.264，分辨率 / 帧率未改"
3. 同时提供原始单镜文件包（zip），让用户可以自己拿原始素材去剪辑软件里做最高质量后期

## 六、交付编码（H.264+AAC）与不压缩画质

### 6.1 交付编码与画质原则

- **最终成片统一封装为 H.264(yuv420p)+AAC、faststart 的 MP4**，确保 Windows 双击、聊天预览、剪映 / Pr / DaVinci 正常播放。
- **画质铁律：不压缩画质、不降分辨率、不降帧率。**
